## 二、问题详情

### P0-1：存根模式下对话被完全丢弃

- **定位**：[add\_conversation](file:///c:/Users/makot/Desktop/Ariadne/dba_pipeline/mcp_server.py#L126-L158)
- **现象**：第三个分支（无 scheduler、无 dba）返回 `"conversation stored, DBA pipeline not wired (stub)"`，但实际既不存文本也不入图，对话直接丢弃。
- **影响**：README 与 tool 描述均暗示存根模式「会存储文本」，但实际是空操作，误导用户。
- **修复建议**：
  - 存根模式下至少将对话追加到内存列表（如 `DBAServer._stub_conversations`），或
  - 明确修改返回消息与 README，说明存根模式不存储任何内容。
- **验收标准**：存根模式下调用 `dba_add_conversation` 后，文本可被追溯（或文档明确声明不存储）。

  【砍掉存根模式，只保留完整dba链路】

### P0-2：intervene 的 create/update 不写向量库

- **定位**：[create\_node](file:///c:/Users/makot/Desktop/Ariadne/dba_pipeline/mcp_server.py#L294-L310) / [update\_node](file:///c:/Users/makot/Desktop/Ariadne/dba_pipeline/mcp_server.py#L312-L326)
- **现象**：`intervene` 直接 `graph.graph.add_node` / 改 `content`，不调用 `vector_store.add_memories`。
- **根因**：`DBAServer` 未持有 `vector_store` 引用（只有 graph/yaml/dba/scheduler/retriever）。
- **影响**：人工创建的节点没有向量，P 链路检索永远找不到；人工更新 content 后向量仍是旧内容。
- **修复建议**：给 `DBAServer` 传入 `vector_store`（或经 `retriever.vector_store` 访问），在 create/update 时同步向量库。
- **验收标准**：人工 create/update 节点后，P 链路能检索到该节点且内容一致。

### P0-3：checkpoint 完整状态无法在重启时恢复

- **定位**：[dba\_checkpoint](file:///c:/Users/makot/Desktop/Ariadne/dba_pipeline/mcp_server.py#L365-L402) vs [main() 启动](file:///c:/Users/makot/Desktop/Ariadne/dba_pipeline/mcp_server.py#L719-L820)
- **现象**：checkpoint 保存了 graph + vector + builder\_state + scheduler\_state 四部分；但启动时只用 `load_graph` 恢复 YAML，从不调用 `restore_checkpoint`，也不恢复 builder\_state / scheduler\_state。
- **影响**：重启后孤立节点追踪、DBA 统计、调度器状态全部丢失，向量索引与 YAML 可能不一致。
- **修复建议**：启动时若检测到 checkpoint 目录，调用完整恢复逻辑（含 builder\_state、scheduler\_state）。
- **验收标准**：重启后调度器/构建器状态与持久化前一致。

### P1-4：query\_memory 的 P 链路异常被静默吞掉

- **定位**：[query\_memory](file:///c:/Users/makot/Desktop/Ariadne/dba_pipeline/mcp_server.py#L200-L202)
- **现象**：`except Exception: pass`，P 链路任何失败都无日志地回退关键词匹配。
- **影响**：无法判断检索为何降级，排查困难。
- **修复建议**：在 except 分支记录 `logging.warning` / `logging.error`，包含异常详情。
- **验收标准**：P 链路失败时能在日志看到原因。

### P1-5：rerank 链路是死代码 + rerank\_k 命名误导

- **定位**：[retrieve\_with\_response](file:///c:/Users/makot/Desktop/Ariadne/dba_pipeline/retrieval/retriever.py#L286-L319) / [query\_memory](file:///c:/Users/makot/Desktop/Ariadne/dba_pipeline/mcp_server.py#L172-L180)
- **现象**：
  - `retrieve_with_response`（含 rerank）只有定义无调用点；`dba_query_memory` 走 `retrieve`，rerank 从未生效。
  - `query_memory` 的参数叫 `rerank_k`，实际传给 `retrieve(seed_k=...)`，语义是「检索种子数」，默认 20 远大于 retriever 默认 5。
- **修复建议**：
  - 明确决策：接入 rerank，或删除 `retrieve_with_response` / `rerank_memories` 死代码。
  - 将 `rerank_k` 改名（如 `seed_k` / `limit`）并调整默认值，消除误导。
- **验收标准**：参数语义与实现一致；rerank 要么生效要么明确移除。

  ✅ 已完成（2026-08-15）：rerank 已重构为 **StoryRank**（见 [0815C——StoryRank重构计划.md](0815C——StoryRank重构计划.md)）：
  - 删除 `retrieve_with_response` / `rerank_memories` 死代码
  - 新增 `retrieve_with_story`（检索 → 连通性粗筛 → StoryRank 故事化 → 回复）
  - `rerank_k` 解除与 `seed_k` 的错误等号：`seed_k` 回归默认 5，`rerank_k` 恢复 rank-k 语义（返回条数上限）

### P1-6：inspect\_graph 双向边导致节点重复

- **定位**：[inspect\_graph](file:///c:/Users/makot/Desktop/Ariadne/dba_pipeline/mcp_server.py#L243-L273)
- **现象**：出边、入边分别遍历并 append 邻居节点；双向边（SCENARIO/SOCIAL/ATTRIBUTE）会让同一邻居重复出现。
- **影响**：返回的 `nodes` 列表含重复节点。
- **修复建议**：用 `seen` 集合去重，或遍历前跳过已加入的邻居。
- **验收标准**：双向边场景下返回节点无重复。

### P1-7：get\_stats 的 node\_types 恒为空

- **定位**：[get\_stats](file:///c:/Users/makot/Desktop/Ariadne/dba_pipeline/mcp_server.py#L404-L416)
- **现象**：返回 `"node_types": {}`，是未完成占位符。
- **影响**：Agent 无法获知各节点类型分布。
- **修复建议**：统计各 `NodeType` 数量填入。
- **验收标准**：返回非空且正确的类型计数。

### P2-8：intervene 与 GraphBuilder 行为不一致

- **定位**：[create\_edge](file:///c:/Users/makot/Desktop/Ariadne/dba_pipeline/mcp_server.py#L336-L347) / [update\_node](file:///c:/Users/makot/Desktop/Ariadne/dba_pipeline/mcp_server.py#L319-L322)
- **现象**：
  - `create_edge` 不校验跳转轴权重（GraphBuilder 会拦截权重为 0 的边），也不对双向类型自动补反向边。
  - `update_node` 的 node\_type 无效时静默忽略，而 create\_node 对无效类型返回 error。
- **修复建议**：复用 GraphBuilder 的校验逻辑（抽公共函数），统一双向边与类型校验行为。
- **验收标准**：intervene 与 GraphBuilder 对相同输入产生一致结果。

### P2-9：检索不过滤 deprecated/forgotten 节点

- **定位**：[\_search](file:///c:/Users/makot/Desktop/Ariadne/dba_pipeline/mcp_server.py#L160-L170) / retriever `_build_result`
- **现象**：关键词检索遍历所有节点（含废弃/遗忘）；P 链路也仅过滤 content 为空。
- **影响**：已废弃/遗忘的记忆仍会被检索返回。
- **修复建议**：在检索层过滤 `deprecated` / `forgotten`，或至少在返回结果中清晰标记。
- **验收标准**：默认检索不返回已废弃/遗忘节点（除非显式要求）。

### P2-10：--vector-dir 路径语义与 checkpoint 保存不一致

- **定位**：[启动加载](file:///c:/Users/makot/Desktop/Ariadne/dba_pipeline/mcp_server.py#L760-L762)
- **现象**：`vector_store.load(args.vector_dir)` 期望的是 FAISS 索引**文件**路径，而参数名 `--vector-dir` 暗示目录；checkpoint 保存的是 `<save_dir>/faiss_index`。
- **修复建议**：统一为「目录 + 固定文件名」，或改参数名为 `--vector-index` 并明确为文件路径。
- **验收标准**：加载/保存路径语义一致，文档清晰。

### P2-11：intervene 与 scheduler 后台线程并发竞争

- **定位**：`scheduler._do_flush`（worker 线程）vs [intervene](file:///c:/Users/makot/Desktop/Ariadne/dba_pipeline/mcp_server.py#L290-L363)（event loop 线程）
- **现象**：两者都修改 graph 并写 YAML，无锁；networkx 图非线程安全。
- **影响**：并发时可能产生脏数据或损坏 YAML。
- **修复建议**：为 graph 修改与 `_save` 引入 `threading.Lock`。
- **验收标准**：并发读写下无脏数据。

### P3-12：\_search 无索引，O(N) 全量扫描

- **定位**：[\_search](file:///c:/Users/makot/Desktop/Ariadne/dba_pipeline/mcp_server.py#L160-L170)
- **现象**：每次检索遍历所有节点做 bigram 相似度，无索引。
- **修复建议**：大图时优先走向量检索，或引入简单倒排索引。
- **验收标准**：检索复杂度可控。

### P3-13：inspect\_graph 无效 node\_id 返回空且无提示

- **定位**：[inspect\_graph](file:///c:/Users/makot/Desktop/Ariadne/dba_pipeline/mcp_server.py#L226-L288)
- **现象**：node\_id 不存在且 topic 为空时返回 `{"nodes": [], "edges": []}`，无错误提示。
- **修复建议**：返回明确的错误信息（如 `{"error": "节点不存在: xxx"}`）。
- **验收标准**：无效 node\_id 时 Agent 能区分「无结果」与「传错 ID」。
