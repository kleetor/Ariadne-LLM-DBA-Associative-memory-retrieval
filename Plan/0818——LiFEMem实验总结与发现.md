# LiFEMem 记忆检索评测完整报告（最终版）

> 实验对象：Ariadne 记忆系统（LLM DBA 管理 + 目的驱动的联想记忆检索 P 链路）
> 评测数据集：LiFEMem（自建自然人完整人生叙事图谱，322 节点 / 410 边）
> 对照基线：Naive RAG（纯向量 top-N）
> 盲评模型：DeepSeek-v4-flash（temperature=0）
> 日期：2026-08-18

---

## 一、实验背景与目标

验证 Ariadne 的 P 链路（目的驱动联想检索：跳转轴 + 目的回归 + 寻峰终止）在**自建完整人生叙事图谱**上的实际表现，核心问题：

1. P 的联想检索相对朴素向量检索（Naive RAG）的增量/差距是什么？
2. P 的"跨场景发散"是缺陷还是设计特性？
3. **什么样的评测范式才与记忆系统匹配？**（本报告最重要的方法论问题）

## 二、数据集与查询集

### 2.1 图谱：LiFEMem

- **规模**：322 节点 / 410 边（含噪声节点 60 个，孤立噪声 38 个，占 11.9%）
- **内容**：单一自然人从高中 → 大专 → 工作的完整人生叙事
  - 高中：成绩优异 → 早恋分心成绩下滑 → 高考压力默默承受 → 高考前夕分手 → 高考失利
  - 大专：浑浑噩噩逃课挂科 → 编程社团 → 慢慢走出困惑 → 自学转码 → 毕业拿 offer
  - 工作：互联网后端开发 → 频繁加班 → 待遇不满 → 想转 AI
  - 家庭（父·刘建国 / 母·王秀兰 / 妹·刘雨桐）、同学（同桌·林晓雨 / 死党·陈浩 / 恋人·苏婉婷）、健康、情绪、社交、噪声
- **边类型**：CAUSAL(168) / SCENARIO(104) / SOCIAL(55) / SEQUENCE(49) / ATTRIBUTE(19) / TEMPORAL(8) / PREFERENCE(7)，7 种覆盖（TAXONOMIC 按跳转轴设计抑制）
- 构建：保留原 216 节点图原样，追加人生叙事 + 跨场景联想边 + 适度噪声（build_lifemem.py 可复现）

### 2.2 查询集三版演进（本身即实验发现）

| 版本 | 形态 | 内容 |
|------|------|------|
| v1 | **问答式**（「用户现在做什么工作？」） | 35 条 7 类 + expected 少量节点 |
| v3 | **陈述触发式**（「最近项目排太满了，天天加班……」） | 35 条 = 30 陈述 + 5 弃权，9 类情境 |
| — | 纯故事对比（无查询） | 仅对 P/RAG 故事成对比较 |

**范式认知**：真实对话中用户与 LLM 是"我/你"关系——用户**表达状态**（「压力好大」），不做明确提问（提问是 RAG 知识库的事）。记忆系统在**无明确提问**的语境下触发：陈述 → 目的推断 → 联想检索 → 记忆 → 回应。

## 三、评测范式演进（四轮修正）

### 3.1 初版：问答式查询 + 五维盲评

所有系统候选统一过 StoryRank 故事化，DeepSeek 按五维 1-5 盲评（相关性 / 连贯 / 完整 / 真实 / 噪音过滤）。

### 3.2 第一轮修正：目的推断类型化

- 发现：P 的事实查询目的推断跑偏（「喜欢喝什么咖啡」被推断出「社交互动」）
- 修正：`PURPOSE_INFERENCE_PROMPT` 类型化（information/emotional 分类）
- 效果实证：q07 目的「社交互动」→「确认细节」，推断层噪声消除

### 3.3 第二轮修正：评判口径与检索范式匹配

- 矛盾：查询字面未指向的内容，目的推断指向了；**评判以查询为主，检索以目的扩展**
- 修正：noise_filter 基于查询目的判定 + 恢复 CROSS_VALID（合理联想率）

### 3.4 第三轮修正：陈述触发式范式（v3）

- 认知：**问答式查询本身即错配**——用户不会对 LLM 提问"他 XX 怎么样"
- 修正：查询重构为**用户第一人称陈述**（30 条）+ 弃权陈述（5 条，隐含图中不存在的信息）
- 实证效果：
  - **目的推断 30/30 精准**（倾诉/寻求安慰/理解原因/确认风险）——回归原生职责
  - P 差距收窄（total 4.51 vs RAG 4.67，v1 为 4.53 vs 4.74）
  - 弃权出现拒答行为（P 1/5，v1 为 0/5）

### 3.5 第四轮修正：三框架评测（决定性）

发现带查询的评测（无论五维还是偏好）都受 **judge 认知偏置**影响后，引入三框架对比：

| 评测框架 | 判定依据 | 结果 |
|------|------|:---:|
| 问答框架·五维（带陈述） | 主题相关性 | RAG 胜（4.67 vs 4.51） |
| 问答框架·偏好（带陈述） | 主题相关性 | RAG 略优（16:14） |
| **记忆框架·纯故事对比（无查询）** | **记忆资产质量** | **P 胜（25:5，83.3%）** |

### 4.4 三框架结果（核心表）

|------|:---:|:---:|------|

### 4.5 案例：s01「天天加班到十一二点」三框架表现

- P 故事独有内容：**脂肪肝/胆固醇**（健康影响）、散步/晨跑/写日记/看动漫（缓解方式）、人生纵深（高考失利→大专→分手→周期性低落）
- RAG 故事内容：加班现状 + 职业背景（小王/通宵修 bug/压榨/小李离职字节/不敢辞职）
- **五维判定**：P 的脂肪肝等被 noise_filter=3 判为噪音（P 4.4 vs RAG 5.0）
- **纯故事判定**：P 胜——"更全面覆盖健康状态、情绪模式、缓解方式与人际支持，便于生成既体谅疲惫又贴合个人的回应"

## 五、评测框架偏差分析（judge 认知偏置）

**核心发现：LLM judge 不懂联想价值。**

1. **相关性判定的本质**：LLM 判断"是否与当前问题相关"使用**主题/字面匹配**——联想内容（加班→脂肪肝）因主题不同被判"偏离"
2. **RAG 的输出天然贴合这种判定**：RAG 按查询字面语义检索，输出必然"相关"——**judge 的相关性标准是 RAG 形状的**
3. **同一个 P 故事**：问答框架里是噪音（noise_filter 3 分），记忆框架里是财富（纯故事 83% 胜）——**不是故事变了，是 judge 的标准变了**

**结论**：带查询的 QA 式评分会系统性低估联想型记忆系统——评判者只认"主题相关"，不认"联想价值"。

## 六、最终方法论论证闭环

### 6.1 记忆检索的行业共识：召回优先

- 检索层宁多勿缺：false positive（多余内容）代价低（下游可滤），false negative（漏掉的记忆）代价高（永久丢失）
- Mem0 / Zep 检索层设计均为高召回 + 后续过滤

### 6.2 检索层 ≠ 最终回复

- 管道：检索（高召回）→ 故事化 → **主聊天 LLM 基于当前对话上下文过滤生成回复**
- 检索层判"噪音"的内容，在主 LLM 环节本来就会被滤除——**用最终回复质量反推检索层质量是评测误用**
- **评测检索层应看召回与记忆价值，而非最终输出精度**

### 6.3 P 多出的部分 = RAG 触及不到的记忆

- s01 实证：RAG 候选（top-41）**没有**脂肪肝/缓解方式——这些节点语义向量与"加班压力"相似度不够，**无论 top-N 多大都进不来**
- P 通过跳转轴（加班→健康→情绪→缓解）触及——**RAG 架构上无法触及**
- 纯故事对比 83% 判定这些独有内容有记忆价值

### 6.4 噪音可优化，漏召回不可修复

- P 的 40-50 条候选含噪音 → **可优化**（收紧容忍带、排序层过滤）
- RAG 漏掉的联想记忆 → **不可修复**（语义匹配架构决定）

### 6.5 反向论证：P 在双重不利下只输 0.16

P 在五维评分中承受**双重不利**（问答框架 + noise_filter 明确把联想当噪音扣分），仍只落后 0.16（4.51 vs 4.67）——**一个被系统性惩罚的系统仍能逼近满分对手，证明其真实质量远超 RAG**。

**规律**：评测框架越公平，P 的优势越明显（问答 0.16 落后 → 偏好五五开 → 记忆框架 83% 碾压）。**低估程度 ≈ 评测框架的偏差程度。**

## 七、关键发现汇总

1. **评测范式决定胜负**：同一套 P/RAG 系统，问答框架下 RAG 胜，记忆框架下 P 胜 83%——评测必须匹配系统定位
2. **LLM judge 存在认知偏置**：带查询的 judge 天然把联想当噪音（只认主题相关），联想价值只能在"记忆资产"框架下评测
3. **记忆系统评测的正确口径**：检索层测召回与记忆价值，最终输出质量不归检索层（主 LLM 会按上下文过滤）
4. **P 的独有联想是 RAG 触及不到的记忆**（s01：脂肪肝/缓解方式），有真实记忆价值（纯故事 83%）
5. **噪音可优化，漏召回不可修复**：P 的膨胀是可控成本，RAG 的漏检是架构硬伤
6. **反向论证**：P 在被噪音惩罚 + 问答框架双重不利下仍只输 0.16——真实质量远超评测所示
7. **目的推断回归原生职责**：陈述触发式下 30/30 精准（v1 问答式下偶发跑偏）
8. **expected 覆盖衡量字面召回**（RAG 0.865 略胜），P 的联想价值在 expected 之外，需用记忆框架捕捉
9. **knowledge_update 是 P 的已知弱点**（联想向前推进、难回溯时点），弃权拒答需机制补齐（P 1/5）

## 八、结论

1. **P 与 RAG 的定位分野**：P = 高召回 + 独特联想价值的记忆检索器；RAG = 精确但低召回的查询匹配器
2. **作为记忆系统**（召回优先 + 下游主 LLM 过滤），P 的架构定位正确；**评测应使用记忆框架**（纯故事对比，P 胜 83%）
3. **问答框架评测记忆系统 = 用阅读理解考百科全书**——评测方法论的偏差系统性低估了联想型记忆系统
4. **遗留可优化项**：P 的输出量膨胀（排序层/容忍带）、弃权拒答机制、knowledge_update 时点对比

## 九、局限与待办

- **局限**：35 条查询样本有限；judge 为 DeepSeek（非 GPT-4o，不可与公开榜直接比）；expected 标注依赖人工；纯故事对比为单模型单次判定
- **待办（P1）**：Mem0 / Graphiti / Letta 外部框架对照；noise_filter 维度重新定义（区分"无关内容"与"合理联想"）
- **待办（P2）**：弃权拒答机制；knowledge_update 时点对比；候选排序层精度截断
