# Ariadne 自建个人记忆数据集评测计划

> 来源：2026-08-18 会话。在项目既有 216 节点自然人记忆数据集基础上扩展为「真正的个人记忆数据集」（LiFEMem，322 节点 / 410 边），参考 LongMemEval 能力维度设计中文查询集（35 条，计划扩至 60–100）。**主指标为故事质量评价**（所有记忆系统候选统一过 StoryRank → DeepSeek 五维评分 + 人工抽检），检索层量化指标（R@all 等）仅作辅助诊断。外部引入 Naive RAG / Mem0 / Graphiti / Letta 做同步对照（全文本出发，公平性声明见 §6.3）。

***

## 一、目标

1. **构建一个连贯、真实、可复现的个人记忆数据集**：LiFEMem（高中→大专→工作完整叙事 + 家庭 + 跨场景联想边 + 噪声），已完成。
2. **端到端评测记忆系统**：统一查询集（7 类能力），主指标为 StoryRank 故事质量（相关性/连贯因果/完整性/真实性/噪音过滤），覆盖本系统 P 与主流外部框架。
3. **公平对照**：全部系统从相同记忆内容出发，主对照不预设正确答案；检索层指标（R@all）作辅助诊断。

### 2.2 扩展一：新增自然人场景（重点：学生时代）

在现有 6 场景上补充生活细节，**以自然人学生时代的场景记忆为主**，每个子场景 10–20 节点：

| 新场景 | 示例内容 |
|--------|---------|

| **学生时代·大专校园** | 专业课、自习室、宿舍生活、室友、食堂、社团活动 |
| **学生时代·社团与社交** | 社团活动、室友、同学关系、校园恋爱、毕业照 |

| 宠物 | 养猫、猫的性格、疫苗日程 |
| 购物消费 | 消费习惯、常用电商、最近大额支出 |
| 旅行 | 旅行偏好、去过的城市、恐高/晕车 |

> **人物具体化设计说明**：同学记忆必须**具体到个人**——每个人物一个 PERSON 节点，content 含姓名，另有 ATTRIBUTE 边挂外貌特征节点（如「同桌林晓雨，扎马尾、笑起来有酒窝」）。示例人物：同桌·林晓雨（马尾、酒窝）、早恋对象·苏婉婷（长发、爱穿白裙子、笑起来眼睛弯弯）、死党·陈浩（眼镜、话痨）。
>
> **早恋记忆设计说明**（高中早恋）：以早恋对象为 PERSON 节点，围绕「情窦初开（EMOTION）→ 传情书（ACTION）→ 偷偷约会（SCENARIO）→ 躲避老师（ACTION/SCENARIO）→ 被老师发现、父母反对（STATUS/SEQUENCE）→ 高考前夕分手（SEQUENCE/TEMPORAL）」构建因果/时序链，走 SCENARIO「教室→天台→放学路上」场景、CAUSAL「恋爱→成绩波动→老师谈话」因果；与同桌场景共用「晚自习/传纸条」节点形成社交圈交叉，供「同桌→恋人→死党」人物关系联想查询复用。
>
> **家庭记忆设计说明**（构成完整社会人际关系）：家庭成员同样**具体到个人**——父亲·刘建国（严肃、话少、跑运输）、母亲·王秀兰（温和、爱唠叨、做饭好吃）、妹妹·刘雨桐（初中生、和用户感情好、爱吃零食）。节点类型：成员为 PERSON、职业/性格为 ATTRIBUTE、家庭氛围为 SCENARIO、经济压力为 REASON/STATUS、亲子互动为 ACTION。**关键：家庭记忆要与同学/早恋/工作场景交叉连边**，形成完整社会人际网——死党·陈浩常来家里玩（家庭×同学）、父母发现早恋并反对（家庭×早恋）、父亲支持用户自学转码（家庭×工作）、母亲认识同桌·林晓雨（家庭×同桌）。
>
> **负面记忆设计说明**（成绩下滑 → 高考压力 → 大专迷失 → 走出困惑）：构成人生低谷-回升主线，全部用节点类型与因果/时序边承载。
> 1. **成绩由好变坏**：高一成绩名列前茅（STATUS）→ 早恋分心、沉迷打游戏（CAUSAL 因）→ 高二成绩跌至中下游（STATUS，deprecated 标记旧成绩节点）→ 月考排名下滑（SEQUENCE）。
> 2. **默默承受高考压力**：不敢告诉父母、独自硬扛（EMOTION：压抑/焦虑；REASON：父母期望高、家里经济压力）→ 深夜失眠（ACTION）。
> 3. **高考前夕分手**：早恋被老师告知父母后被迫收心，高考前夕与苏婉婷分手（STATUS/EMOTION：失恋、情绪跌到谷底；SEQUENCE）→ 带着低落情绪走进考场。
> 4. **高考失利**：考上一所普通大专（STATUS/REASON：落差、失落）。
> 5. **大专浑浑噩噩**：逃课、打游戏、挂科、迷茫迷失（STATUS/ACTION/EMOTION：混日子、找不到方向）。
> 6. **大学时期慢慢走出困惑**：大二被室友拉着参加社团、偶然接触编程（SCENARIO/SEQUENCE）→ 渐渐找到兴趣、开始规律学习（ACTION）→ 大三系统自学编程（ACTION，与职业场景衔接）→ 毕业拿到后端开发offer（STATUS）。
> 类型标注原则：低谷期的「状态」用 STATUS + deprecated 时间演进，「原因」用 REASON，「情绪」用 EMOTION，节点间用 CAUSAL/SEQUENCE/TEMPORAL 连边，保证 P 检索能沿「成绩好→下滑→高考压力→分手→高考失利→大专迷失→慢慢走出困惑→转码」链条走通。

### 2.3 扩展二：时序异质化记忆节点（核心）

同一主题在不同时间的**演进/矛盾记忆**，用于支撑知识更新与时序查询。表达方式（三种并用）：

1. **content 内嵌时间**：如「用户2024年3月靠喝咖啡提神」「用户2024年9月已戒咖啡，改喝龙井」。
2. **deprecated 标记**：旧节点标 `deprecated: true`（保留历史，不参与检索），新节点为活跃状态——与 DBA 的 deprecate 机制行为一致。
3. **TEMPORAL 边**：新节点连 TEMPORAL 边到时间表述节点，支撑跳转轴的时间维扩展。

典型时序主题建议（**共 9 个**，每主题 2–4 个节点，含旧/新状态；其中 5 个与学生时代相关）：

| 主题 | 演进线 |
|------|--------|
| 职业 | 后端开发 → 转岗架构 |
| 咖啡习惯 | 喝咖啡提神 → 胃疼 → 戒咖啡改喝茶 |
| 运动 | 不运动 → 晨跑 → 受伤休养 → 恢复 |
| 居住地 | 大学宿舍 → 租房 A 市 → 换租房 |
| 体重/体检 | 体检异常 → 调整饮食 → 复查好转 |
| 学习方向 | 高中成绩优异 → 早恋分心成绩下滑 → 高考前夕分手 → 高考失利 → 普通大专浑浑噩噩 → 大学期间慢慢接触走出困惑 → 自学转码 |
| 同桌友谊 | 高中同桌打闹 → 毕业失联 → 工作后重逢 |
| 早恋 | 情窦初开 → 传情书早恋 → 躲避老师 → 成绩下滑 → 被老师发现 → 高考前夕分手 |
| 兼职→工作 | 校园兼职 → 毕业转正 |

## 四、标注协议

1. **人工标注 expected 集**：每条查询标注 gold 记忆节点 id 集合（可含多条），并注明所属能力类别。**仅作检索层辅助诊断**，不构成主比较依据（见 6.3 声明）。
2. **故事质量评价（主指标）**：
   - 所有系统候选 → StoryRank 故事化 → DeepSeek 按五维（相关性/连贯因果/完整性/真实性/噪音过滤）1–5 打分 + 总分；
   - 弃权类单独评：「无相关记忆」应被体现；
   - 人工抽检 20%，报告与 DeepSeek 的一致性（对齐论文 Fleiss' κ 做法）。
3. **辅助判定**：R@all 命中比对（expected 语义等价判定）；跨场景输出由 DeepSeek 标注 ✓/~/✗（描述性）。

## 五、评测指标

### 5.1 主指标：故事质量评价（StoryRank 统一故事化 + LLM/人工评分）

**所有记忆系统**的检索候选统一经 Ariadne StoryRank 故事化后，由 DeepSeek 按五维评分、人工抽检 20%：

| 维度 | 含义 | 说明 |
|------|------|------|
| 相关性 | 故事与查询的匹配程度 | 检索方向是否正确 |
| 连贯/因果 | 故事是否有逻辑与因果结构 | P 的边信息在此体现（外部框架无此优势，但公平） |
| 完整性 | 查询相关的关键记忆是否被覆盖 | 召回充分性 |
| 真实性 | 忠实于记忆原文，不编造 | 防幻觉 |
| 噪音过滤 | 无关/干扰记忆是否被排除 | 对应 LESS 维度 |

总分 = 五维加权均分（1–5）。弃权类查询单独评：故事应体现「无相关记忆」。

**输入适配**：P 输出含边的因果链路；外部框架输出为记忆文本列表 → 统一转为 `{nodes, edges}` 结构喂 StoryRank（外部框架 edges 为空）。

### 5.2 辅助诊断指标（保留，仅用于分析检索层，不构成主比较依据）

| 指标 | 口径 | 说明 |
|------|------|------|
| R@all / P@5 | expected 命中 | 召回诊断；expected 依赖边正确性假设，不作主结论 |
| CROSS_OUT | 跨场景输出占比 | 描述性 |
| token / 延迟 | 每查询检索消耗 | 成本维度 |

### 6.2 外部主流框架对照（公平性）

在相同数据与查询集上同步测评主流记忆框架，验证 Ariadne 的相对水平：

| 基线 | 类型 | 实现方式 | 检索机制 | 新增依赖 |
|------|------|---------|---------|---------|
| **Naive RAG** | 纯向量基准 | 自研（复用项目 embedding + FAISS） | 向量 top-k | 无 |
| **Mem0** | 主流记忆层 | `pip install mem0ai` | 语义 + BM25 + 实体多信号 | mem0ai |
| **Graphiti** | 时序知识图谱 | `getzep/graphiti` + Kuzu 嵌入式 | 向量 + 全文 + 图遍历混合 | graphiti、kuzu |
| **Letta(MemGPT)** | 虚拟内存 | `letta`（archival memory 检索） | 归档记忆向量检索 | letta |

**公平性原则（五同）**：
1. **同数据**：LiFEMem 322 个节点 `content` 铺平为 322 条记忆条目，各框架写入完全相同的文本（含 deprecated/forgotten 节点，模拟原始记忆）。
2. **同查询**：统一使用 [LiFEMem_queries.yaml](file:///c:/Users/makot/Desktop/Ariadne/data/LiFEMem_queries.yaml)（35 条，后续扩展）。
3. **同指标**：主指标为 StoryRank 故事质量五维评分（§5.1）；辅助诊断 R@all/P@5/CROSS_OUT。
4. **同判定**：DeepSeek 联想视角判定统一应用于所有框架输出。
5. **同 embedding**：统一 bge-large-zh-v1.5（本地），排除 embedding 差异成为变量。

**结果映射**：框架输出为记忆文本 → 经 `content→id` 映射表还原节点 id → 与 expected 比对算 R@all。若输出与节点 content 存在改写，由 DeepSeek 判定语义等价性。

**输出配额**：R@all 用各框架全量输出；P@5 统一截断 top-5。

> 注意：Graphiti/Letta 偏 agent 控制流，作为"记忆检索器"接入而非完整 agent；每框架独立 venv 隔离依赖。

### 6.3 公平性讨论与方法论声明（2026-08-18 定稿）

对「数据集是否为 P 专门设计」与「边是否构成外挂」两点的方法论结论：

**1. 数据集构造偏差（存在，方向偏向 P）**：
- expected 标注沿图邻接节点反推（多跳/跨场景查询的 gold 集依赖边结构）；
- 边类型对齐跳转轴权重矩阵（回避权重 0 方向）。
- 这两点与图质量无关，属评估协议层偏差 → **在报告中如实披露**。

**2. 边的信息不对称（成立，但有反证）**：
- 仅 P 加载人工 gold 图，外部框架只有文本 → 信息不对称存在；
- 但反证：Ariadne 的完整链路本为「对话 → DBA 自动建图 → P 检索」，LiFEMem 人工图为一次性粗略构造（无 DBA 的持续纠错/边审计），**信息保真度不高于 DBA 自动维护图**，gold 图不构成对 P 的优势输入；
- 图结构是知识图谱方法（P 与 Graphiti 共享）的本质特性，非 P 独有附加手段。

**3. 结论性实验设计**：
- 主对照（对外表述为「给定结构化记忆时的检索能力对比」）照跑：P 用 gold 图，外部框架用文本，配 6.3 声明；
- **主指标改用故事质量评价**（§5.1）：所有系统候选统一过 StoryRank → 五维评分。该设计**不预设正确答案**，直接消除「expected 沿边反推」的协议层偏差，且对 P 与外部框架完全对称（P 有边信息是公平的被测特性，非外挂——因为故事质量由 LLM/人工独立评价，不依赖边的正确性假设）；
- 报告含「方法论声明」小节，记录以上三点。

## 七、执行步骤

1. **数据扩展**：写新增节点/边进 `data/`（新文件如 `memory_graph_v2.yaml`，不改原文件），完成 300–450 节点图谱。
2. **查询集编写**：写 60–100 条中文查询 + 人工 expected 标注（`queries` 段，格式对齐 loader 的 `load_queries`）。
3. **评测脚本（本系统）**：复用 `retriever.retrieve()`（P 链路），对每条查询输出候选集。
4. **框架接入脚本**：
   - `frameworks/naive_rag.py`：322 条记忆条目入向量库，查询 top-k。
   - `frameworks/mem0_runner.py`：Mem0 add 全部条目 → search 每条查询。
   - `frameworks/graphiti_runner.py`：Graphiti 建图（每条记忆为 episode/fact）→ 混合检索。
   - `frameworks/letta_runner.py`：Letta archival memory 写入 → 检索。
5. **故事化与评价**：各系统候选统一 → StoryRank 故事化 → DeepSeek 五维评分 + 弃权单独评；人工抽检 20%。（R@all 等仅作辅助诊断）
6. **汇总报告**：故事质量主对照 + 检索层辅助诊断，对齐论文 MORE/LESS/CROSS 分析。

| 时序类弱于联想类 | 无有效性窗口，只有 content 内嵌时间 + TEMPORAL 边 |
| 弃权类 P 明显优于外部框架 | P 有目的过滤/deprecated 过滤；纯向量框架无拒答机制 |

**风险**：
- 故事评分者（DeepSeek）对「带边故事 vs 无边故事」的评分偏置 → 见决策点 D1（盲评 + 维度权重）。
- 候选配额不对等导致故事量纲不可比 → 见决策点 D2（统一 top-k）。
- 外部框架中文适配与"公平配置"界定 → 见决策点 D5。
- 弃权类对纯向量框架天然不公平 → 见决策点 D3。
- 评测可复现性（LLM 随机性） → 见决策点 D6。
