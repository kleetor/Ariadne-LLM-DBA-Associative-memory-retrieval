# Graphiti 基准对比接入报告（LiFEMem v3）

> 实验对象：Graphiti（graphiti-core 0.29.3，Neo4j 5.26-community 后端）
> 评测数据集：LiFEMem（322 节点 / 410 边）+ LiFEMem_queries_v3（35 条陈述触发式）
> 对照系统：Ariadne P 链路 / Naive RAG / Mem0（qdrant）
> 日期：2026-08-21
> 关联计划：《0818——自建个人记忆数据集评测计划》T7 / 里程碑 6

## 核心结论（速览）

### ① 三指标总览：排位方向相反，不可互相替代

| 指标（性质） | 排位 | 关键数值 |
|------|------|---------|
| **检索层 expected 覆盖**（辅助诊断，原文节点级召回） | **RAG/Mem0（纯向量）> P > Graphiti** | 0.840 > 0.765 > 0.642；跨场景率 Graphiti 0.678 最高 |
| **故事质量五维盲评**（T6 主指标，带查询目的） | **Graphiti > RAG > P** | 4.74 > 4.67 > 4.51（Graphiti 连贯 4.87 / 噪音 4.53 双第一） |
| **纯故事选择**（无查询，长期记忆价值） | **P > RAG > Graphiti** | 26:4 / 25:5 / 23:6（P 全面占优） |

> 三条证据链各自指向不同排位：检索层看"原文节点召回"，五维看"回答查询的组织质量"，纯选看"作为记忆的信息丰富度"。**任一单一指标都会导向片面结论**，详见 §九。

### ② 检索层结论（辅助诊断）

- Graphiti expected 覆盖 0.642 垫底。损失归因（§4.3）：修复前 28 个未命中 **57% 抽取丢失 + 43% 检索遗漏**，召回天花板仅 0.802。
- **写入侧修复实验（§4.4）**：Graphiti 有原生持续抽取/修正能力，重入 14 条丢失原文后进图率升至 **100%**；但覆盖未随修复提升——**检索排序（top-N 内）才是主导瓶颈**。修复结论限定于小批量补录场景，不构成全量写入可靠性的断言。
- 跨场景增益（+0.03~0.05）与 expected 损失（-0.11~0.19）**不是"精度换联想"的交换关系**。

### ③ 概念定论（详见 §十）

1. **纯向量是记忆系统检索的最优默认方案**（相对图谱与关键词，除联想检索外）：纯向量 expected 覆盖最高（0.840）、BM25 中文失效、图谱仅在联想检索维度有价值。
2. **RAG 与图谱评比中 RAG 领先**：Graphiti 落后根因已定位（事实级检索集中效应 + 抽取合并信息收窄，§9.7；StoryRank 反证排除故事化责任，§9.8）。
3. **Mem0 图谱功能定论：不引入**——实体 boost 依赖 spaCy 英文启发式，中文关系查询可预见与 BM25 同一下场；"图谱+向量+关键词"三查叠加过于牵强且成本失控。
4. **知识库 ≠ 记忆系统**（脑科学视角）：记忆系统对应**情景记忆（海马体）**，知识库对应**语义记忆（颞叶新皮层）**——同属外部上下文工程但机制与意图不同。**后续方向：探讨二者真正分离与合作，而非堆叠检索方法**。

### ④ 工程要点

- **后端**：Neo4j 取代计划中的 Kuzu（上游弃用）；Docker `neo4j:5.26-community`（neo4j/lifemem2026，bolt 7687），Kuzu 保留为无服务器回退。
- **LLM 适配（最大卡点）**：`extra_body={"thinking": {"type": "disabled"}}` 关闭 thinking 后 content 直出完整 JSON，全量 322 条建图约 20 分钟（5 组参数实测确认）。
- **中文适配缺口**：个别 fact 被输出为英文；Neo4j 全文索引对中文 BM25 弱（向量+图遍历兜底）。
- **方法学**：字数 ≠ 故事质量（4 轮 120 次对照验证，§9.9）；P 的联想扩展存在个别幻觉风险（s23，个案不系统化，§9.8）。

## 一、后端决策：Kuzu 弃用 → Neo4j（含 Mem0 图谱对接展望）

### 1.1 为什么放弃计划中的 Kuzu

| 维度 | 结论 |
|------|------|
| 上游维护 | Kuzu 项目已停止维护；graphiti-core 0.29.x 对 Kuzu 后端发 `DeprecationWarning`（"will be removed in a future release"） |
| graphiti 0.29.3 Kuzu 后端质量 | 存在多个未修复 bug（见 §七）：`add_episode_bulk` 访问不存在的 `driver._database`；`build_indices_and_constraints` 为 no-op 导致 FTS 索引缺失；FTS 索引为静态快照（先建索引后插数据查不到）；数据仅在 `Database.close()` 时落盘（GC 关闭不落盘） |
| 对比公允性 | Graphiti 的检索依赖全文/向量/图遍历，Kuzu 的 FTS 中文弱 + 无向量索引，混合检索降级为纯图遍历，无法代表 Graphiti 真实水平 |

### 1.2 为什么选 Neo4j（对齐用户诉求）

- **Graphiti 主后端**：Neo4j 5.26+ 是 Graphiti 官方首选（原生 FULLTEXT + RANGE + VECTOR 索引，混合检索完整）。
- **为 Mem0 图谱功能铺路**：Mem0 graph memory（`add(infer=True)` 建实体图谱）的 `graph_store` 仅支持 Neo4j/Memgraph。**当前 Neo4j 容器即为后续 Mem0 图谱对接的同一实例**——届时 Graphiti 与 Mem0 各自建 schema（Graphiti 的 Episodic/Entity/RelatesToNode_ 与 Mem0 的 entities/relations），共享一个图数据库底座，避免另起服务。对接步骤见 §八建议。
  > ⚠️ **后续修正（§10.1）**：2026-08-21 已定论 **Mem0 图谱功能不引入**（中文实体 boost 依赖 spaCy 英文启发式、三查叠加成本失控）——本节"为 Mem0 铺路"考量已被取代；Neo4j 仍保留为 Graphiti 后端，对接展望仅存档。
- **部署方式**：本机 Docker 运行（Docker Desktop 由用户启动后 daemon 可用）；容器配置：`neo4j:5.26-community`，`NEO4J_AUTH=neo4j/lifemem2026`，heap 512m/1g、pagecache 256m。Neo4j 下载源（dist.neo4j.org 403 / fossies 401 / archive.org 连不上）与 Docker daemon 曾为本环境障碍，均经用户配合解决。

## 二、LLM 适配：关闭 thinking（本次卡点主因）

### 2.1 现象与根因

api.gpt.ge 的 `deepseek-v4-flash-0731` 是**推理模型**，默认开启 thinking：

| 现象 | 说明 |
|------|------|
| `content` 为空 | `response.choices[0].message.content` 为 None → EmptyResponseError → 默认重试退避最长 120s，极慢 |
| `content` 截断占位 | 实测 `{"extracted_entities": []}`（26 字符）等不完整 JSON，`extracted_entities`/`edges` 大面积为空 → 建图抽出 0 实体 |
| `reasoning_content` 巨大 | 单次调用推理最长 29,963 字符，输出预算被推理占用；`max_tokens=8192` 时 content 被截断（实测 8192 必截断、16384 多数完整） |

### 2.2 修复：请求参数关闭 thinking（5 组参数实测）

| 参数（extra_body） | reasoning_len | 结论 |
|------|:---:|------|
| 无 | 224 | 默认开启 thinking |
| `{"thinking": {"type": "disabled"}}` | **0** | ✅ 关闭（采用） |
| `{"reasoning": {"enabled": false}}` | 121 | 仍思考 |
| `{"enable_thinking": false}` | 0 | ✅ 亦可 |
| `{"reasoning": null}` | 370 | 无效 |

采用 `extra_body={"thinking": {"type": "disabled"}}` 后：`reasoning_content` 归零、`content` 直出完整 JSON。全量 322 条建图约 **20 分钟**完成（关闭前仅 3 条就需 60-90s 且结果残缺）。

### 2.3 配套稳定性修补（RobustOpenAIGenericClient）

1. **空列表弃答重试**：仅对抽取类 schema（含 `extracted_entities`/`edges` 字段）拒绝全空列表并重试；去重类（`duplicate_facts` 等）空列表是合法结果，不误伤。
2. **空 choices 抖动重试**：`response.choices` 偶发为空（端点抖动），内部 6 次短退避重试（1~5s），不走默认 120s 长退避。
3. **reasoning 兜底**：content 解析失败时从 `reasoning_content` 尾部提取最后一个合法 JSON（防其他端点）。
4. **强制合并抽取**：graphiti 0.29.3 的 bulk 路径默认"节点+边分开抽取"（每 episode 2 次 LLM 调用，中文弃答率高），monkeypatch 强制走合并抽取（单次调用，实测更可靠）。

### 4.3 expected 损失归因（对"跨场景增益 vs 精度损失不成比例"的回应）

**核心质疑**：Graphiti 跨场景覆盖率仅比 P 高 0.03、比 RAG 高 0.05，但 expected 覆盖比 P 低 0.11、比 RAG 低 0.19——比值失衡，"精度换联想"的说法不足以解释如此大的损失。本节给出损失拆解。

**方法**：对每个未命中的 expected 节点，用 Neo4j 检查其 episode uuid 是否被任一 `RELATES_TO` 边的 `episodes` 数组引用——被引用=「已进图（内容已建成可检索事实）」；否则=「抽取丢失（写入侧从未建成事实）」。（脚本 `eval/analyze_graphiti_loss.py`）

**结果**（30 条非弃权，81 个 expected 节点）：

| 来源 | 数量 | 占未命中比例 |
|------|:---:|:---:|
| **A. 抽取丢失**：节点 content 从未被 LLM 抽成任何 fact（图中不可达） | 16 | 57.1% |
| **B. 检索遗漏**：节点已在图中，但未进入 top-N 候选 | 12 | 42.9% |

**推论**：

1. **召回天花板 = 0.802（65/81）**：81 个 expected 中仅 65 个在图中。即便 Graphiti 检索完美，expected 覆盖上限也只有 0.802——仍低于 RAG 的 0.840（-0.038）。**写入侧抽取表示损耗是 Graphiti 相对 RAG 的硬约束**，与检索无关。
2. **检索层实际缺口 = 0.148**（0.802 − 0.654，即 12 个检索遗漏）：这是真正的检索/排序差距，含 top-N 配额效应（如 s07 配额仅 10）。
3. **损失与跨场景增益相互独立，不是交换关系**：跨场景增益（+0.03/+0.05）来自图遍历的联想召回，而 expected 损失主要来自写入侧抽取丢失 + 事实级检索排序，二者不能互相抵消。**之前的表述"expected 对 Graphiti 系统性低估"过于乐观，需修正**：低估只在"改写后事实 vs 原文节点"的度量口径上成立，但**信息保真损失（抽取合并/丢弃）是真实存在的**。
4. **保真度权衡的真实画像**：Graphiti 的抽取/合并是"写入方"设计（把 322 条原文收敛为 228 实体 / 268 边，合并掉大量原子事实）。这在对话流场景是优点（去冗余），但在本评测"原文事实可召回性"口径下是净损失。**主指标故事质量（T6）可判定这种合并后的图谱表达是否仍保留足够事实供故事化**——这是对"信息保真"更直接的度量。
5. **逐条胜负分化**：Graphiti 在**学习/社交/感情**类查询上反超 P（s17/s23/s28），在**怀旧/生活/健康**类（尤其学生时代大专段）偏弱——后者的抽取质量不足（见 §六 中文适配）。
6. **弃权类 5/5 有候选**：与 P/RAG/Mem0 一致，Graphiti 检索层同样无拒答机制（故事质量主指标中弃权单独评）。

### 4.4 写入侧修复实验（Graphiti 持续抽取/修正能力验证）

**问题**：Graphiti 本身是否具备"持续抽取 + 修正"能力？若有，可对写入侧缺陷做修复测试；若无，则需保留缺陷再另做修复。

**核实结论：有**，能力分三层：
1. **持续抽取（增量）**：`add_episode / add_episode_bulk` 可随时追加 episode，图增量更新，无需全量重算；
2. **去重/合并（写入侧自愈）**：每次入库的实体/事实解析与既有图去重合并（resolve_extracted_nodes/edges）；
3. **显式修正 API**：`add_triplet`（直接注入事实三元组）、`graphiti.nodes.entity.save` / `graphiti.edges.entity.save`（手动改节点/边）、时序矛盾自动 `invalidate`（双时态模型）。

**实验（`eval/repair_graphiti_extraction.py`）**：把 14 个抽取丢失节点（对应 16 次未命中）的**原文 content 作为新 episode 重新入库**（原生持续抽取 + 去重合并机制，非旁路），随后重建 episode 映射并重跑 35 条查询。

**结果**：

| 指标 | 修复前 | 修复后 |
|------|:---:|:---:|
| expected 节点进图率（被任一 fact 引用） | 80.2%（65/81） | **100%（81/81）** |
| expected 覆盖 | 0.654 | 0.642 |
| 未命中来源 | 57.1% 抽丢 + 42.9% 检漏 | **0% 抽丢 + 100% 检漏** |

**结论**：
1. **写入侧缺陷可修复且成本极低**：仅重入 14 条原文，进图率即达 100%。Graphiti 的持续抽取 + 去重合并机制成功把"图中不可达"的节点全部变可达（重复 episode 与既有图合并，无数据爆炸）。
2. **但 expected 覆盖未随写入修复提升**（0.654→0.642，差异属排名重排噪声）：修复后全部未命中转为"在图中但未进 top-N"——**真正的瓶颈是检索排序（P 配额内），而非写入抽取**。
3. **对 Graphiti 的修正结论**：先前归因的"抽取表示损耗"经修复实验证伪为**可消除**（write-side 非硬约束）；检索排序 gap 才是主导约束，后续优化方向是**检索配置**（reranker / RRF 权重 / 混合搜索参数 / top-N 配额），而非写入。修复后图保留 14 个追加 episode，作为"修复态"基线（`graphiti_candidates.json` 现为修复后输出）。

> **实验限定（DBA 视角）**：本修复仅重入 14 条原文，100% 进图率只证明**小批量重入的抽取稳定性**，不能外推为"大容量写入无丢失"——全量 322 条初建时确有 14 条（17%）未建成事实，说明**写入侧在大批量下仍可能丢失信息**。此为写入方（Ariadne 中对应 DBA 建图环节）的固有风险，修复机制只能作为补救手段，不能替代写入质量；对本实验的"写入可修复"结论应限定在补录/增量场景，不作全量可靠性断言。

## 五、方法论含义（对齐《0818 计划》）

1. **对 P 的对照价值**：Graphiti 与 P 同属图谱范式，其检索层表现可作为"图方法"的公平参照：expected 覆盖不如语义向量（0.642 vs 0.840），跨场景联想略强（0.678 vs 0.634）。结合 §4.4 修复实验，这一差距**主要来自检索排序而非写入**——若以"同一写入侧修复基线"对比，P 与 Graphiti 的图方法差异更集中在排序与联想策略上。
2. **主指标仍是故事质量（T6）**：检索层 expected 沿原文节点标注、以 top-N 配额计，对事实级输出的 Graphiti 有口径低估；主对照（StoryRank 五维盲评）对所有系统对称，才是公正的排位依据。Graphiti 候选已按统一格式输出（含 `fact` 字段），可直接进 T6 故事化管道。
3. **与 Mem0 的定位差异**：Mem0（flat entries + 向量）是"扁平记忆层"；Graphiti（时序知识图谱）与 P 同属"图谱结构记忆"。二者检索层行为差异显著（Mem0=RAG 同序；Graphiti 因图遍历产生额外召回），佐证了 0819 报告中"后续对照转向图谱结构系统"的定案。

## 六、中文适配缺口（披露）

1. **抽取输出语言不稳定**：`get_extraction_language_instruction` 要求"与原文同语言"，但部分 fact 被模型输出为英文（如 `User enrolled in 吴恩达的机器学习课程.`）。不影响候选 id 映射与 R@all，但影响故事化文本质量，已披露。
2. **BM25 中文弱**：Neo4j 全文索引默认 Lucene 标准分词，对中文按单字 token 索引，无词级匹配。混合检索实际由**向量 + 图遍历**承担（与 Mem0 的 BM25 中文失效同因，但 Graphiti 有图遍历兜底，影响小于 Mem0）。如需 BM25 中文生效需自定义 Lucene 分词器（未做，披露）。
3. **学生时代·大专段检索偏弱**：s06/s14/s15/s22/s29 等查询 0 命中。修复实验（§4.4）表明这些节点修复后**均已在图中**（进图率 100%），未命中属检索排序问题而非抽取缺失，后续优化方向为检索配置。

## 九、三系统查询结果对比（T6 故事质量主指标）

对 P / Naive RAG / Graphiti 的检索候选统一经 StoryRank 故事化 → DeepSeek 五维盲评（匿名，temperature=0）。P/RAG 评分沿用 08-19 v3 批（同协议），Graphiti 为 08-21 新评（`eval/outputs/story_scores_graphiti.json`），时间差属已知轻微不一致。

### 9.1 总览（30 条非弃权，1-5 分）

| 系统 | total | 相关性 | 连贯因果 | 完整性 | 真实性 | 噪音过滤 | 联想合理 cv |
|------|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| **Graphiti** | **4.74** | 4.73 | **4.87** | **4.60** | 4.97 | **4.53** | 0.89 |

| P | 4.51 | 4.70 | 4.47 | 4.47 | 4.97 | 3.93 | 0.81 |

两两对比（total）：**P vs Graphiti：3 胜 / 10 平 / 17 负**；P vs RAG：6/7/17；RAG vs Graphiti：6/13/11（接近）。

### 9.2 关键发现

1. **主指标排位与检索层完全反转**：检索层 expected 覆盖 Graphiti 垫底（0.642 < P 0.765 < RAG 0.840），但故事质量 Graphiti 居首（4.74 > 4.67 > 4.51）。说明 Graphiti 即使漏掉部分"原文节点级"命中，其**事实级输出经故事化后依然完整可用**——检索层的形态性低估在主指标下得到补偿。
2. **连贯因果（4.87）与噪音过滤（4.53）双第一**：Graphiti 输出的是抽取合并后的事实（含边结构），StoryRank 从中构建的因果链条更干净；P 的噪音过滤仅 3.93（联想扩展多，cv 0.81 最低）。
3. **真实性全 4.97（天花板）**：三系统均无编造。
4. **按类别**：Graphiti 在 social（5.00）、work_pressure（5.00）、learning（4.87）、future（4.90）领先；nostalgia/relationship 类别 RAG 领先；life 类三者都弱（s21/s22 全部低分）。
5. **弃权类**：仅 P 对 s34（狗子掉毛）正确拒答（refused=True），RAG/Graphiti 全部 0/5——**弃权能力仍是本批次共性问题**（P 也只在 1/5 上成功），与计划"弃权类 P 明显优于外部框架"的预期不符，需单独复盘（见 §九.4）。
6. **候选重叠（Jaccard 均值）**：P∩Graphiti 0.149（最发散）、P∩RAG 0.198、RAG∩Graphiti 0.328（共享向量底座）——三系统检索视角差异显著，故事质量差异非"候选趋同"造成。

### 9.5 方法学注释

- **评分压缩效应**：三系统 total 均 ≥4.5，分差小（4.51→4.74），判别力集中在连贯/噪音两维；真实性与完整性已趋天花板。若需拉开区分度，可考虑维度加权或人工抽检校准（D1 盲评+同权为 08-18 定案，未改）。
- **时间不一致**：P/RAG（08-19）与 Graphiti（08-21）分两次评，temperature=0 同协议，但跨会话仍可能有轻微漂移；如需严格同批可整体重跑（成本约 40 分钟）。
- **故事长度**：Graphiti 故事 81-528 字符（均值 ~270），与 P/RAG 同量级，无长度偏置证据。

1. **纯选择测"故事作为长期记忆本身的丰富度"**：P 的图检索（边扩展 + 目的回归 + 寻峰）生成的故事**维度更多、细节更具体**（学历/工作/健康/情绪/人际/目标多线覆盖），LLM 判词反复出现"覆盖维度多、细节具体可信、更有助长期理解用户"；Graphiti 的抽取-合并把 322 条原文收敛为精炼事实，信息密度与细节量显著更低。
2. **五维测"故事回答查询的贴合度与组织质量"**：Graphiti 输出更聚焦查询、更连贯、噪音更少（连贯 4.87 / 噪音 4.53 双第一），在查询相关维度得分高。
3. **一致性佐证**：P 的噪音过滤 3.93 五维最低、cv 0.81 最低——联想扩展丰富=信息多=噪音也多，同一特性的两面。纯选择奖励前者，五维惩罚后者。
4. **Graphiti 胜出分布**：对 P 仅胜 4 条（s08/s09/s12/s14，均情绪/怀旧类），对 RAG 胜 6 条（s08/s14/s21/s23/s26/s29，含 4 条仅胜 RAG）——**s08/s14 是 Graphiti 纯选唯一稳定强项**（同时击败两者，因果叙事链完整），其余多为"第二优于 RAG 但不及 P"。
5. **平局极少**：三轮共 90 次对照仅 1 平（s20 RAG vs G，判词"信息、细节与连贯性完全等价，仅表述顺序略有差异"），判别基本无模糊。

**方法学含义**：若目标是"长期记忆的信息价值"，P 的图检索显著占优；若目标是"回答具体查询的组织质量"，Graphiti 略优。**两指标不可互相替代**——建议主报告同时呈现两条证据链（查询贴合度 vs 记忆丰富度），避免单一指标导向片面结论。

**典型样例全文对比**（5 个查询：s02/s08/s11/s14/s22，含三系统完整故事 + LLM 评判）：见 `eval/outputs/story_compare_3sys.md`（生成脚本 `eval/gen_story_compare.py`）。样例覆盖两种指标的胜者与最大分歧，可直接引用作报告附录素材。

### 9.7 Graphiti 故事质量垫底归因（StoryRank 前后两环节拆解）

**问题**：纯选择下 Graphiti 故事质量最低（P > RAG > Graphiti，26:4 / 23:6）。是检索/映射层（StoryRank 前）还是故事化层（StoryRank 后）的问题？（诊断脚本 `eval/diag_graphiti_story.py`）

**A. 候选层（StoryRank 前）——问题主因**：

| 指标 | P | Naive RAG | Graphiti |
|------|:---:|:---:|:---:|
| 平均候选数 | 38.3 | 38.3 | **33.6** |
| 候选达配额上限（>38）的查询数 | 17/35 | 17/35 | **9/35** |
| 候选场景覆盖均值（跨人生维度数） | 7.6 | 8.4 | **6.8** |
| 场景覆盖 < RAG 的查询数 | — | — | **31/35** |

- **事实级检索的"集中效应"**：Graphiti 检索返回与查询语义最近的事实及其图邻域，天然聚焦查询主题；而 RAG 的纯向量 top-k 散落在不同人生维度。结果 Graphiti 候选平均少 4.7 个、仅 9/35 达配额，且跨场景跨度更窄（31/35 查询低于 RAG）。
- **抽取-合并的信息收窄**：322 条原文被 LLM 抽取合并为 228 实体 / 268 边，检索命中事实再展开回原文节点——只有被 fact 引用的 episode 能回来，信息面被"压扁"。
- **协议因素**：为公平（同数据），故事喂的是原文 content 而非 Graphiti 的事实文本（`fact` 字段仅存档未入故事），Graphiti 的事实级表达在故事化中被旁路。

**B. 故事层（StoryRank 后）——忠实反映输入，非缺陷**：

| 指标 | P | Naive RAG | Graphiti |
|------|:---:|:---:|:---:|
| 故事长度均值（字符） | 467.6 | 358.2 | **265.1** |
| 故事长度中位数 | 490 | 362 | **267** |
| 专有信息命中均值（人名/课程/项目等） | 5.2 | 3.2 | **2.2** |

- 输入少且集中 → 输出短、细节少：故事长度排序 467 > 358 > 265 与纯选排位 P > RAG > Graphiti **完全一致**，专有信息命中 5.2 > 3.2 > 2.2 亦同——纯选判词反复出现的"覆盖维度多、细节具体可信"正是由这两项承载。
- 外部系统均走 `story_rank_for_texts`（文本列表、无边）；Graphiti 与 RAG 同为文本输入，但输入量更少。StoryRank 本身是忠实的"输入整理器"，不放大也不补偿输入差异。

**结论**：
1. **问题出在 StoryRank 之前（检索/映射层），不在 StoryRank**。Graphiti 的"事实级检索 + 抽取合并 + 原文映射"三个环节共同把候选收窄、聚焦，导致 StoryRank 输入信息量不足 → 故事单薄 → 纯选（信息丰富度维度）垫底。
2. **与五维评分的统一解释**：同一种"聚焦"特性，五维（查询贴合度）奖励它（连贯 4.87 / 噪音 4.53 双第一），纯选（记忆丰富度）惩罚它（故事短、细节少）。
3. **接入协议影响**：若改用 Graphiti 的事实文本（而非原文 content）喂 StoryRank，故事化输入的信息组织方式会变（更精炼/更连贯），是后续可验证的接入选项——但会偏离"同数据"公平协议，需单独声明。

### 9.8 反证实验：P 的故事 vs Graphiti 原始事实文本（StoryRank 不是削弱点）

**假设检验**："StoryRank 把 Graphiti 的候选压缩成 265 字故事，削弱了其信息量"——若成立，直接用 Graphiti 检索返回的**原始事实文本**（`fact` 字段，未过 StoryRank，均值 667 字/查询，33.6 条事实）与 P 的故事对比，Graphiti 应显著回升。

**结果（30 条非弃权，同协议纯选）**：

| 对比 | P 胜 | 对方胜 | 平 | P 胜率 |
|------|:---:|:---:|:---:|:---:|
| P vs **StoryRank 后的 Graphiti** | 26 | 4 | 0 | 0.867 |
| P vs **原始事实文本** | **28** | 2 | 0 | **0.933** |

**结论——假设不成立，方向反了**：
1. **原始事实文本比 StoryRank 故事输得更惨**（2 胜 vs 4 胜）。StoryRank 实际**提升**了 Graphiti 在纯选下的表现——把碎片事实整理成连贯叙事，让判官更容易评估其"记忆价值"。
2. **判词印证格式决定胜负**：P 胜的理由反复出现"故事B仅为碎片化条目堆砌，缺乏组织与深度"；原始事实文本（34 条 bullet）即使信息量更大（667 字 vs 265 字），在"组织连贯"维度上被系统性扣分——纯选评测的是"作为组织化记忆的价值"，不是原始信息含量。
3. **Graphiti 垫底的根因重新确认**：不在 StoryRank（它反而是加分项），而在**候选层的信息量与组织度**——事实级检索候选少而集中（§9.7），且其事实文本本身是碎片条目，二者共同限制了故事化的天花板。
4. **个别案例的幻觉风险（不系统化）**：s23 判词指出 P 的故事"包含推测性细节"（如证书、论文、朋友评价），原始事实"更忠实于原始记忆"。经查 P 的 s23 故事确实出现"在 Coursera 上拿到了课程证书"等细节——**属个别查询上的模型幻觉/StoryRank 补充，非 P 检索的系统性问题**，且不影响该查询的整体故事判断；此类个案需在人工抽检环节核实，不上升为系统结论。

### 9.9 反证补充：故事字数 ≠ 故事质量（数据验证）

对四轮纯选共 120 次对照统计"胜者字数更长/更短"：

| 对比 | 更长者胜 | 更短者胜 | 平 |
|------|:---:|:---:|:---:|
| P vs Graphiti（故事） | 83.3% | 16.7% | 0 |
| Naive RAG vs Graphiti（故事） | 83.3% | 13.3% | 1 |
| P vs Naive RAG（故事） | 90.0% | 10.0% | 0 |
| **P vs Graphiti 原始事实** | **10.0%** | **90.0%** | 0 |

**结论**：
1. **字数与质量无单调关系**：前两轮"故事 vs 故事"中更长者胜率高（83-90%），是因为更长者携带了**更充分且组织良好**的信息（长度是丰富内容的副产品）；但"P 故事 vs 原始事实"中，**字数最长者（事实列表，均值 667 字）输掉了 90%**——长度完全不保证质量。
2. **真正的决定因素是"信息的组织与真实性"**：原始事实（最长但碎片化）系统性被罚"缺乏组织与深度"；P/RAG 故事（较长但连贯）被奖"有结构、易理解"。**长度只是相关，不是因果**。
3. 对评测协议的含义：故事质量比较**无需也不应做长度对齐**；纯选判词已显式要求"不要把'故事更长'当作更好"（PAIR_PROMPT 内置该约束）。

## 十、概念总结与后续研究方向（2026-08-21 定稿）

### 10.1 记忆系统检索技术的定位结论

基于本轮全部对照（检索层 expected / 五维盲评 / 纯选择 / StoryRank 反证 / 写入修复），对记忆系统检索技术的定位：

1. **纯向量是记忆系统检索的最优默认方案**（相对图谱与关键词，除联想检索外）：
   - 检索层：RAG / Mem0（纯向量）expected 覆盖 **0.840**，高于 P（图谱 0.765）与 Graphiti（图谱 0.642）；
   - 关键词（BM25）在中文下已证失效（Mem0 接入即退化回纯向量，0819 报告）；
   - 图谱仅在**联想检索**维度显示价值（P 的跳转轴 / 目的回归 / 寻峰：跨场景率 0.656 且纯选记忆价值最高）。
   - **定位**：记忆系统默认走纯向量；图谱只作联想扩展的可选增强，不作检索主干。

2. **RAG 与图谱评比中 RAG 领先**：
   - 检索层 RAG（0.840）> P（0.765）> Graphiti（0.642）；
   - Graphiti 落后根因已定位：事实级检索的集中效应 + 抽取合并的信息收窄（§9.7），StoryRank 反证排除故事化责任（§9.8）；
   - Graphiti 五维唯一领先（连贯 4.87 / 噪音 4.53）是"聚焦"特性的副产品，同被纯选（信息丰富度 0.642 垫底）惩罚——图谱精炼表达对"查询贴合"友好，对"记忆保真"不利。

3. **Mem0 图谱功能定论：不引入**：
   - Mem0 graph memory 的检索期实体 boost 依赖 spaCy **英文**启发式（0819 报告），中文需另配且收益存疑；
   - 可预见与 BM25 中文失效同一下场：**引入新机制却无检索增益，最终退化为纯向量**；
   - 即便意外取得成果，"图谱 + 向量 + 关键词"三种查询方法叠加也过于牵强，且**未考虑成本控制**（双索引/多图维护、推理与存储成本）。

4. **复杂度约束**：Graphiti 混合检索（向量 + BM25 + 图遍历三查叠加）在本数据上未带来任何检索层优势；单一纯向量机制已是性价比最优解。**检索机制不是越多越好，应随场景取最适配的单一路径**。

### 10.2 知识库与记忆系统的分离与合作（脑科学视角）

知识库与记忆系统虽同属**外部上下文工程**（都为 LLM 提供上下文），但**将其混为一谈过于草率**：

| 维度 | 记忆系统（本项目） | 知识库（RAG 类） |
|------|------------------|----------------|
| 脑科学对应 | **情景记忆（episodic memory）** | **语义记忆（semantic memory）** |
| 核心脑区 | **海马体（hippocampus）**，编码/提取个人经历与情景 | **大脑皮层 / 颞叶新皮层（neocortex / temporal lobe）**，存储通用概念与事实 |
| 数据性质 | 个人经历、时序、情感绑定、高冗余 | 通用知识、静态、去个人化 |
| 检索意图 | 回忆具体经历（联想 / 时序敏感） | 查询事实概念（精确 / 稳定） |
| 更新机制 | 增量写入 + 遗忘 / 冲突处理（deprecate、时序演进） | 知识更新与校验 |

**共同点**：都是外部上下文的存取，都需要检索、排序与更新。

**差异点**：数据性质、检索意图、核心机制均不同——如同海马体与新皮层分工不同。

**后续研究方向**：继续探讨 **agent 的记忆系统（情景记忆）与知识库（语义记忆）的真正分离与合作**——各自采用最适合的检索机制（记忆走向量 + 情景联想，知识走向量 + 精确召回），并明确二者接口（何时查记忆、何时查知识、如何融合），而非在同一系统里堆叠所有检索方法。本轮"图谱三查叠加无收益"的实证，恰好支持"分离而非堆叠"的方向。
