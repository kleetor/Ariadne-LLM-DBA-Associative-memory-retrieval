## 摘要

在**情感陪伴**（系统基石）场景下，以**结构化记忆上下文块**为评测对象、**同题并排一次判定**为判分方式，对三系统做同一批 comprehensive 数据对照，得到以下互补结论：

1. **质量（多模型判分，主判分 qwen，70 条非弃权）**：Ariadne **4.74** > Graphiti **3.63** > Mem0 **2.99**；Ariadne vs Mem0 **+1.74**（64 胜 / 2 平 / 4 负）、vs Graphiti **+1.10**（62 胜 / 4 平 / 4 负）。
2. **排位跨模型稳健**：qwen / deepseek-v4 / gemini / gpt-5.6-luna 四个有效模型**均列 Ariadne 第一**（4.17~4.74）；**同族的 deepseek 反而给 Ariadne 最低分（4.17）**，反证无同族自偏好。
3. **token 用量（内部 LLM，非回复侧）**：三系统"在已规模化库/图上写入 1 条"的单次成本**均不随图规模增长**（Ariadne 2.4k / Mem0 ~9.2k / Graphiti ~10.45k）；会话级 Ariadne ~18k / Mem0 ~58k / Graphiti ~63k。检索注入随规模增长的**只有 Graphiti**（facts 50→102→210，token 888→1785→3635）。
4. **检索完整性分两类**：Ariadne 候选恒 26 = **自然收敛**（PAR 寻峰 + 目的回归，检索完整）；Mem0 恒 8 = **`top_k=8` 硬截断**（深度/丰富度损失，且图越大裂口越大）。
5. **（辅，0828 抽取）**：DBA 自动建图为"双重压缩"（节点压缩 43%、边压缩 72%）；经"两步拆分 + 激进连边"改造后节点召回 75–76%、边召回 34.8%、边类型一致率 77.1%；**gold 图非最优、图结构一致性要求低**（边重合 34.8% 仍可打平/反超，4 次独立抽取纯故事恒定 4.725）。

> ⚠️ **口径声明**：质量侧结论限定于**同批 comprehensive 数据 + 人工构建的纯情景记忆数据集**条件；judge 主观判分方差仍存在，报告给方向 + 区间而非单个小数。token 侧为**记忆系统自身**的检索/写入 LLM 开销（嵌入模型与回复侧 token 不计）。

## 一、测评定位与对象

### 1.1 主：0831 e2e（情感陪伴场景）

- **场景定位**：情感陪伴是系统最初建立的基石（DBA 建图 → 联想检索 → StoryRank 表达的原点），行走在"情景记忆/陪伴"一侧而非"知识库/事实问答"一侧。
- **评测对象**：**系统喂给模型的结构化记忆上下文块**——Ariadne=`{story}`、Mem0=`{memories}`、Graphiti=`{entities,relations}`。**不生成回复做判分**，把回复 LLM 与记忆系统解耦，judge 只评该块作为陪伴素材的质量。
- **判断方式**：**同题并排一次判定**——每题把三系统上下文块同题一起交给 judge 相对比对，各打 1–5 分（避免绝对打分全 5 天花板）。
- **四系统对齐**：Ariadne（tool-calling 按需检索 + StoryRank 故事化）、Mem0（中文补丁：jieba + zh spaCy，向量+BM25 混合）、Graphiti（自托管 + Neo4j 5.26，时态图谱 + 三路混合检索）；同 embedding（bge-large-zh-v1.5）、同候选配额（D2 按 Ariadne 输出 N 对齐）。

### 1.2 辅：0828 抽取评测（DBA 写图质量）

- 作为记忆系统的**上游/写入侧**维度：LLM DBA 如何把口语化对话持续转化为结构化记忆图谱，直接决定下游检索/判分的上限（§4.10 "联想链路的前置性"）。
- 与 e2e 的衔接：e2e 判分的是"检索→组装→判分"这一**下游闭环**；0828 抽取评测补上"建图质量/结构一致性"这一**上游**，两段合起来覆盖记忆系统全链路。

## 三、0831 e2e 主测①：多模型对最终产物的评分（质量侧）

> 判分对象 = **结构化记忆上下文块**；judge 模型各打 3 维 1–5 分；样本量 76 条（非弃权 **70 条**）。

### 3.1 主判分总均分（qwen3.8-flash，70 条非弃权）

| 系统 | total | 记忆丰富度 | 易理解性 | 用户建模度 |
|------|:---:|:---:|:---:|:---:|
| **Ariadne** | **4.74** | 4.57 | 4.89 | 4.76 |
| Graphiti | 3.63 | 4.11 | 2.73 | 4.06 |

**两两对比（70 条，total 均值差 + 胜率）**：

- Ariadne vs Mem0：**+1.74**（64 胜 / 2 平 / 4 负）
- Ariadne vs Graphiti：**+1.10**（62 胜 / 4 平 / 4 负）
- Mem0 vs Graphiti：**-0.64**（Graphiti 55 胜 / 9 平 / 6 负）

### 3.2 按类别 total 均值

| 类别 | Ariadne | Mem0 | Graphiti |
|------|:---:|:---:|:---:|
| single_fact | 4.76 | 3.14 | 3.57 |
| preference | 4.71 | 2.96 | 3.67 |
| multi_hop | 4.89 | 3.19 | 3.52 |
| knowledge_update | 4.89 | 2.89 | 3.67 |

| assistant_behavior | 4.63 | 3.08 | 3.58 |

### 3.3 观察（方向性）

1. **Ariadne 全面占优（+1.10~+1.74）**，各类别均 4.29~4.89；**联想类（multi_hop / knowledge_update / temporal / cross_scene）达 4.86~4.89**——StoryRank 故事化把带边因果路径整合为有陪伴价值的故事，覆盖关键记忆。
2. **易理解性是三系统最大分野**：Ariadne 4.89 vs Mem0 2.29 / Graphiti 2.73——Ariadne 输出有叙事结构的故事块，Mem0/Graphiti 是扁平记忆文本/实体列表。（该差异属**完整管线对比的正当结果**：Ariadne 管线含 StoryRank 重排步骤，非"形态不对称"折损。）
3. **mixed_memory 类差距最小**（Ariadne 4.29 vs Graphiti 3.92 / Mem0 2.83）——用户+助手混合记忆检索下，Graphiti 候选更贴近，差距收窄。
4. **弃权/过滤类（6 条，单独呈列不进总分）**：Ariadne 普遍高于 Mem0/Graphiti（如 q28/q76 弃权 Ariadne 5.00；仅 q75 被 Graphiti 4.00 反超）——目的过滤/遗忘机制作为 Ariadne 独有能力。

## 四、0831 e2e 主测②：token 用量

> 定义：统计记忆系统「自身」在每轮对话中因检索/写入而调用的 LLM 的 **input+output token 累加**（重复侧即"系统喂给模型的内容注入量"）。**嵌入模型与回复侧 token 不计**。

### 4.1 写入/抽取侧：单次写入成本（不随图规模增长）

对等口径：在**已规模化的库/图上写入 1 条**的增量成本（Graphiti 为"已建 N 规模图 group 上逐条 `add_episode` 1 条"）。

| 写入操作 | N=50 | N=100 | N=200 | 趋势 |
|---|---|---|---|---|
| Ariadne write(maintain) | 2394 | 2394 | 2394 | **恒定**（2.4k） |
| Mem0 add(infer) | 9230 | 9055 | 10175 | **平**（~9.2k） |
| Graphiti 增量单条ingest | 10419 | 10451 | 10524 | **平**（~10.45k） |

### 4.2 会话级聚合（6 轮 + 1 次换话题；三者都处理 6 条消息，对等）

| 系统 | 单次写入 | 会话级 | 趋势 |
|---|---|---|---|
| Ariadne | write 2.4k | ~18k（6×write + 2×search） | **恒定** |
| Mem0 | add ~9.2k | ~58k（6×add） | **恒定** |
| Graphiti | 增量ingest ~10.45k | **~63k（6×增量ingest）** | **恒定** |

> 冒烟会话（6 轮 + 1 次换话题）实测：Ariadne **15418** / Graphiti **41151** / Mem0 **49500**；比值 Mem0 ≈ **3.2×**、Graphiti ≈ **2.7×** Ariadne。

**关键结论**：
- 三系统"单次写入"**都不随图规模膨胀**（Ariadne 2.4k / Mem0 9.2k / Graphiti 10.45k 全部平坦）——抽取器一次只处理"一批新内容 + 有限上下文"，不把整图塞进每次调用。
- Ariadne `maintain` 恒定 2.4k、单次最低；结合 search 低频（2 次/会话），**会话级 ~18k 为三系统最低**。
- Mem0 / Graphiti 单次写入相当（~9.2k / ~10.45k）且恒定；会话级 ~58k / ~63k。其成本增长主要由"每条消息都 ingest + 单次较大"的**轮数累积**造成，而非"图越大单次越贵"。

### 4.3 检索侧：注入量 vs 检索完整性（需区分两类"恒定"）

| 检索侧 | N=50 | N=100 | N=200 | 趋势 |
|---|---|---|---|---|
| Ariadne 候选数 | 26 | 26 | 26 | **自然收敛** |
| Ariadne story注入token | 415 | 331 | 367 | **平**（~330-420） |
| Ariadne search LLM | 1773 | 2111 | 1733 | 平（~1.7-2.1k） |
| Mem0 返回条数 | 8 | 8 | 8 | **硬截断**（top_k=8） |
| Mem0 记忆注入token | 217 | 245 | 267 | **平**（~217-267） |
| Mem0 search LLM | 0 | 0 | 0 | 非 LLM |
| Graphiti 返回facts | 50 | 102 | 210 | **增长**（≈2×） |
| Graphiti fact注入token | 888 | 1785 | 3635 | **增长**（≈2×） |
| Graphiti search LLM | 0 | 0 | 0 | 非 LLM |

**关键结论（检索侧）**：
1. **⚠️ "恒定"≠优势：Ariadne 的 26 与 Mem0 的 8 性质完全不同**——
   - **Ariadne 候选恒 26 = 自然收敛**（PAR 寻峰终止 + 目的回归拦截）：26 已是该查询在该图内的**完整相关集合**，是"检索完整/不遗漏"的体现，非人为设限。
   - **Mem0 返回恒 8 = `top_k=8` 硬截断**：库内可能有更多相关记忆但只取 top-8，代价是**检索深度与丰富度大幅下降**；**图越堆越大时被砍掉的潜在相关记忆越多，丰富度损失被放大**，而该损失不出现在 token 数字里（被截断的没进上下文）。
   - 因此不能把"Ariadne 与 Mem0 都不随规模增长"等同视之。若把 Mem0 `top_k` 调到 26，其注入量与深度会上升（也更接近 Ariadne 覆盖）。
2. **Graphiti 是唯一检索侧随规模线性放大的系统**：facts 50→102→210、注入 token 888→1785→3635（≈2×）——**图谱遍历出的更大子图**作为上下文注入，图越大返回越多。其注入增长**完全来自"返回 fact 数量增多"而非单条变长**（单条 fact ~17.5 字符恒定），属"数量型"膨胀。
3. **量级对比（检索注入量，非写入成本）**：N=200 时 Graphiti 检索注入 3635 token，明显高于 Ariadne story(367) / Mem0(267)——若主 LLM 上下文窗口紧张，Graphiti 在大规模下会先成为瓶颈。

### 4.4 全链路 LLM 调用点覆盖核对（确认统计完毕）

| 系统 | 阶段 | LLM 调用点 | 实测 llm_calls |
|---|---|---|---|
| **Ariadne** | search | `infer_purpose`（目的推断） | search=2 次 |
| | search | `story_rank`（StoryRank 故事化） | 计入 2 次内 |
| | write | `maintain`→triage + node_chain + edge_chain | write=3 次 |
| **Mem0** | add | `add(infer=True)` 抽取+增/删/改合并 | add=1 次 |
| | search | 向量+BM25 混合 | **0（非 LLM）** |
| **Graphiti** | ingest | `add_episode` 合并抽取 | 逐条 6 次/条 |
| | search | 混合检索+图遍历 | **0（非 LLM）** |

- 嵌入模型 token（bge-large-zh）一律不计；检索侧注入量（story/memories/facts）单独按 cl100k 计，属回复侧上下文量，不计入"系统内部 LLM 调用 token"。

## 五、交叉一致性验证（多模型，§8.2）

### 5.1 多模型系统总均分与排位（非弃权 70 条）

| judge 模型 | 区域 | Ariadne | Mem0 | Graphiti | 排位 |
|------|:---:|:---:|:---:|:---:|:---:|
| qwen3.8-flash（主判分） | zh | **4.74** | 2.99 | 3.63 | Ariadne > Graphiti > Mem0 |
| deepseek-v4-flash | zh | **4.17** | 3.30 | 3.56 | Ariadne > Graphiti > Mem0 |
| gemini-3.7-flash | en | **4.56** | 3.56 | 3.31 | Ariadne > Mem0 > Graphiti |
| gpt-5.6-luna | en | **4.43** | 3.37 | 3.55 | Ariadne > Graphiti > Mem0 |
| glm-4-flash（病态，作废） | zh | 3.97 | 3.55 | **4.85** | Graphiti > Ariadne > Mem0 |

### 5.2 两两一致性（有效模型对）

| 模型对 | top-1 一致率 | Cohen kappa | Spearman 秩相关 |
|------|:---:|:---:|:---:|
| qwen vs deepseek | 0.771（54/70） | +0.408 | +0.692 |
| qwen vs gemini | 0.871（61/70） | **+0.579** | +0.647 |
| qwen vs gpt-5.6-luna | 0.814（57/70） | +0.389 | +0.672 |
| deepseek vs gemini | 0.757（53/70） | +0.424 | +0.663 |
| deepseek vs gpt-5.6-luna | 0.743（52/70） | +0.388 | +0.673 |
| gemini vs gpt-5.6-luna | 0.843（59/70） | +0.547 | +0.655 |

### 5.3 结论

1. **Ariadne 占优在 4 个有效模型下均稳健**：qwen（4.74）/ gemini（4.56）/ gpt-5.6-luna（4.43）/ **deepseek（4.17）** 都把 **Ariadne 排首位**（Mem0/Graphiti 仅在第 2/3 名间交换）。→ "Ariadne 全面占优"不是单模型自偏好产物。
2. **两两 top-1 一致率 0.74~0.87、kappa +0.39~+0.58（次强~中等）、Spearman 0.65~0.69**——四模型对"谁是最好"的判断一致性为中等偏上，符合主观判分（陪伴场景）的预期水平。
3. **⚠️ 关键观察：同族的 deepseek 反而给 Ariadne 最低分（4.17，四模型最低）**——若存在"同族自偏好/越近越捧"，同族的 deepseek 应对 Ariadne 给更高分；但它反而给最低。从反方向证明**无同族自偏好**，Ariadne 占优跨模型稳健（DeepSeek 作为批判型模型，对 `{story}` 可能在"是否讲得太满/主观渲染"上更苛刻，故整体压分，但**排位方向未变**）。

## 六、语言/文化偏差检测（§8.3）

> 初衷：gemini / gpt-5.6-luna 为国外模型，担心其对中文陪伴语境（宣泄/共情/委婉拒绝）的判断与国内模型存在语言/文化偏差。

### 6.1 中文组 vs 国外组（系统均分差 zh−en，仅有效对照模型）

| 系统 | zh（qwen+deepseek） | en（gemini+gpt） | 差 | 倾向 |
|------|:---:|:---:|:---:|:---:|
| Ariadne | 4.45 | 4.49 | **−0.04** | 几乎无差 |
| Mem0 | 3.15 | 3.47 | −0.32 | 国外略高 |
| Graphiti | 3.60 | 3.43 | +0.17 | 中文略高 |

### 6.2 结论

1. **Ariadne 占优在 4 个有效模型下全部成立**（含同族 deepseek），说明不是"同族模型集体偏好"。
2. **中文组 vs 国外组的 Ariadne 均分差仅 −0.04**——**未观察到国外模型对中国语境的系统性偏差**（Mem0 −0.32、Graphiti +0.17 属中等幅度且方向不一致，无单调语言偏差信号）。
3. **glm-4-flash 不能作为 judge 对照组**：其对 `{entities,relations}` 形态无差别打满分（Graphiti 60/70 条 5 分、均分 4.85），与其余模型一致性骤降（top-1 0.17~0.19、kappa≈0），已作"**judge 质量退化 / 形态偏好**"案例披露并显式排除，而非"语言偏差"结论。
4. **glm-4-flash 判分结论作废（保留记录）**——仅作为 judge 形态偏好案例。

## 七、0828 辅助评测：DBA 抽取环节（写图质量）

> 本节作为**上游/写入侧**补充，说明记忆系统"建图"质量；与 e2e 的"检索→组装→判分"下游闭环衔接。数据限定在人工构建的纯情景记忆数据集（LiFEMem 322 节点 / 392 边，勘误 410）。

### 7.1 双重压缩（改造前）

| 配置 | 节点召回 | 节点精确 | 边 | R@all* |
|------|:---:|:---:|:---:|:---:|
| gold 子图 | — | — | 138 | 91.67% |
| 逐轮（15 次维护） | 54% | 81.8% | 53 | 0.00% |
| 批量 6（3 次维护） | 49% | 86.0% | 38 | 20.00% |
| DBA 节点 + gold 边（混合图） | — | — | — | 48.00% |

\* R@all 为**重标口径**（为 DBA 图独立重标 expected）。批量 6 节点压缩 **43%**、边压缩 **72%**；**混合图实验（补 gold 边）R@all 由 20.00% 回升至 48.00%（2.4 倍）→ 边连接是检索跑偏的直接原因。**

### 7.2 边压缩归因（A/B/C）

| 类别 | 占比 | 含义 |
|------|:---:|------|
| A 正确连接 | 2.9% | DBA 连对了 |
| B 两端都抽到但未连 | 26.8% | LLM 连边判断/可见性问题 |
| **C 一端节点缺失** | **70.3%** | **节点压缩直接导致无法连边** |

> 机制：改造前 node/edge ops 在同一次 LLM 输出中产生，LLM 连边只能引用「top-15 相关节点 + 一跳邻居 + 本轮新建」，可见节点集合直接限制连边能力。**结论：边压缩是节点压缩的下游果（70% 归因），LLM 独立保守连边仅占 27%。**

### 7.3 改造：两步拆分 + 激进连边

| 版本 | 节点 | 边 | 边召回 | 边精确 | 边类型一致 |
|------|:---:|:---:|:---:|:---:|:---:|
| v1 合并式（基线） | 57 | 38 | 2.9% | 15.8% | 33% |
| v2 两步（无示例） | 99 | 126 | 26.1% | 34.9% | 52% |
| v3 两步+克制 few-shot | 98 | 118 | 23.2% | **37.3%** | 52% |
| **v4 两步+激进 few-shot** | 87 | **170** | **34.8%** | 35.9% | **77.1%** |

> **激进连边（v4）定为当前策略**："宁可多连"在 PAR 检索下安全（寻峰/目的过滤兜底），多连不伤检索；克制版连得过少、联想路径断裂。v4 定案依据是**边召回 / 边类型一致最高**（34.8% / 77.1%），而非子集 R@all（小样本单次不可靠）。

### 7.4 全量验证（322 节点闭环）

- 实质节点召回 **75.2%**（197/262，排除噪声后与子集 76% 一致）、精确 77%、边 529（新边 218）。
- 噪声过滤全量生效：噪声批（60 节点）被 DBA triage 主动跳过（node_ops=0）。
- 全量检索联动：gold **77.78%**（63/81）vs DBA **50.46%**（55/109，重标口径）；分场景中 **nostalgia DBA 6.2% vs gold 90.9%（DBA 独差而非两图共弱）**，而 **social/future DBA 反超 gold（+28/+25pp）**。

### 7.5 结构性结论：gold 图非最优，图结构一致性要求低

| 测评范式 | gold | DBA | 结果 |
|------|:---:|:---:|------|
| 检索 R@all* | 81.82% | 29.09% | gold 大幅领先 |
| 带查询·五维盲评 | **4.06** | 3.54 | gold 胜（差距在相关性） |
| 纯故事·无查询四维 | 4.575 | **4.75** | **DBA 反超** |

> gold 138 边 vs DBA 170 边，**边重合率仅 34.8%**。4 次独立抽取 DBA 纯故事总分**全部恒为 4.725、全部高于 gold**——**DBA 自动建图不劣于人工 gold 图**。要点：① 与 gold 的一致性不是敏感变量；② **完整性仍必要**——边不是"连对"而是"有边可走"（混合图实验）；③ 建图优化应转向「保证连通完整」而非「追求与 gold 结构一致」。

### 7.6 检索层鲁棒性（补测）

| 指标 | v4 | v5 | v6 | v7 | std |
|------|:---:|:---:|:---:|:---:|:---:|
| 节点召回 | 76.0% | 76.0% | 76.0% | 75.0% | ±1.0% |
| 边召回 | 34.8% | 37.7% | 33.3% | 34.1% | ±4.4% |
| DBA R@all（重标口径） | 29.1% | 58.6% | 37.7% | 50.8% | **±11.4pp** |

> **检索层波动远大于故事层**（纯故事恒定 4.725，而重标口径 R@all 范围 29.1%–58.6%、std ±11.4pp）；**任何单次 R@all 数字不可作精确对比依据**，但方向性结论（gold ≫ DBA）仍稳健（两区间不重叠）。此即 0831 e2e 主判分改用"同题并排一次判定 + 扩大样本至 76 条"的直接动机之一。

## 八、综合结论（主 + 辅）

| 维度 | Ariadne | Mem0 | Graphiti | 结论 |
|------|:---:|:---:|:---:|------|
| **质量（judge 判分，70 条）** | **4.74** | 2.99 | 3.63 | Ariadne 全面占优（+1.10~+1.74），跨 4 模型稳健 |
| **写图/抽取（0828 辅测）** | 节点召回 75–76%、边召回 34.8%、边类型一致 77.1% | — | 抽取合并信息收窄（322→228 实体/268 边） | 单次写入成本均不随图规模增长；Ariadne 单次最低 |
| **token（内部 LLM 会话级）** | ~18k | ~58k | ~63k | Ariadne 最低（≈1/3 于侵入式） |
| **检索注入随规模** | 恒定（自然收敛 26） | 恒定（top_k=8 硬截断） | **增长**（facts 50→210） | 仅 Graphiti 真正随规模放大；Mem0 省 token 牺牲丰富度 |

**最终定位**：情感陪伴场景（系统基石）下，Ariadne 在 **质量（多模型判分）+ token 成本（内部 LLM 单次/会话最低）+ 检索完整性（自然收敛）** 三个维度均优于侵入式 Mem0 / Graphiti；辅以 0828 抽取评测确认其**上游建图质量**（DBA 自动建图不劣于人工 gold 图、图结构一致性要求低）。

> 结论均限定在**人工构建的纯情景记忆数据集条件**与**同一批 comprehensive 数据**下；judge 主观判分方差仍存在，报告给方向 + 区间。
