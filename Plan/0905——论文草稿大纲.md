## 2. 摘要（Abstract，~250–300 字，最后写）

**建议结构**（对应"问题 → 方法 → 评测 → 结论"四句法）：

1. **问题**：对话系统长期记忆面临两个子问题——非结构化日志如何持续转成结构化图谱（上游），以及如何有方向、不偏离地从中召回记忆（下游）。现有向量/图谱检索共享「关联强度 = 语义相似度或图距离」的隐含假设。
2. **方法**：提出 Ariadne——① LLM DBA（把记忆图谱当作 LLM 自主维护的数据库，CRUD 指令集 + 三层上下文 + 遗忘机制）；② PAR 有向联想检索（跳转轴 + 目的回归 + 峰值容忍带）；③ StoryRank 故事化组装。
3. **评测**：在情感陪伴场景、comprehensive 数据集（163 节点 / 76 查询）上，以「结构化记忆上下文块」为对象、同题并排 + 多模型交叉判分，对照 Mem0 与 Graphiti。
4. **结论**（关键数字，来自 0908 实验论文文档）：Ariadne 质量 4.74 > Graphiti 3.63 > Mem0 2.99（跨 4 模型稳健）；内部 LLM token 会话级 ~18k / Mem0 ~58k / Graphiti ~63k（单次写入 Ariadne 2.4k / Mem0 ~9.2k / Graphiti ~10.45k，均不随图规模增长）。

> ⚠️ 摘要要写明**口径声明**：质量结论限定在人工构造纯情景记忆数据 + 同批 comprehensive 数据；judge 主观判分给「方向 + 区间」而非单个小数；token 侧不计嵌入模型与回复侧。

## 3. 引言（Introduction）

### 3.1 问题定义（承 0828 两篇）
- 长期记忆的两个子问题：**前置数据管理**（日志→图谱）+ **在线检索**（图谱→召回）。
- 用「压力大→加班→喝咖啡→拿铁→意大利咖啡文化」的例子点破现有方法的失效模式：**缺乏方向感**。

### 3.2 核心挑战（承 0828 前置 §1.2 / PAR §1.1）
- 上游：领域开放性、长期可维护性、指代消解与省略补全。
- 下游：语义相似度 ≠ 功能相关；无向多跳扩展会漂移；固定 top-K 会错过深层跨域路径。

**评测方法演进的动机（0818–0825 → 0908）**：早期用 expected 字面标注模式（R@all / P@5 / expected 覆盖 / 带查询五维）量化系统，但该模式测的是「字面/语义命中人工预期节点」，天然偏纯向量、无法度量联想/发散区价值；证据是「带查询五维里 P 输、纯故事/纯选择里 P 大幅反超（26:4 / 25:5）」——同一系统换评判范式方向即颠倒。故 **0818–0825 的 expected 量化数据一律不可用作结论**，仅作「评测方法缺陷」的动机素材；有效质量结论只看 0908 e2e 的四模型 judge 判分。

### 3.3 本文主张与贡献（Contribution，列表式，最重要）
建议 4–6 条，每条约 2 行：
1. **LLM DBA 架构**——记忆数据库模型 + CRUD 指令集 + 三层上下文 + 异步调度 + 边衰减遗忘。
2. **PAR 检索模型**——跳转轴（有向类型化权重矩阵）+ 目的回归（推断/过滤/加权）+ 峰值容忍带（替代固定 top-K）。
3. **组件维度分化的消融证据**——跳转轴主召回深度、目的过滤主召回-输出量权衡、目的加权主精度微调（A2/A6 因果证据）。
4. **StoryRank 故事化**——把候选因果链组装为可直接消费的故事块。
5. **记忆系统评测方法学重构**——批判 expected 字面标注模式（其在联想价值上系统性失效，故事二元化反转即证），提出「结构化记忆上下文块 + 同题并排 + 多模型 judge 交叉」新范式。
6. **三系统对照实证**——情感陪伴场景下 Ariadne 在质量（4 模型判分）与成本上优于 Mem0 / Graphiti。

## 5. 方法（Method）

### 5.1 系统总览（一张架构图 + 一段话）
- 图：`对话日志 → DBA 维护 → MemoryGraph+VectorStore → PAR 检索 → StoryRank → 回复`（承 0828 前置 §1 全链路图）。
- 说明三个组件的上下游衔接：**图谱质量决定检索上限，检索候选决定故事化质量**。

### 5.2 组件一：LLM DBA（上游建图）

> 对标：主流文档知识图谱法（GraphRAG / LightRAG 一类，泛称）为一次性全量抽取；本文区别在 LLM 增量可纠错维护 + 遗忘机制。

小节（每节 1–2 段 + 关键表格）：
1. **记忆数据库模型**：节点=主键记录、边=外键索引、LLM=DBA。
2. **节点/边类型体系**：6 节点类型表 + 8 边类型表（含方向性）。
3. **三层上下文 + 维护判断**：对话/记忆/结构三层，`k=15` 硬限制（不随图规模膨胀，prompt ~2k token）。
4. **CRUD 指令集**：create/update/fix_type/deprecate + create/delete 边。
5. **GraphBuilder 执行与校验**：语义去重、类型校验、双向边补全、事务保护、孤立遗忘。
6. **调度器**：五层触发策略、寒暄不累积、M=6 批量。
7. **遗忘机制**：边衰减而非时间衰减（LLM 主动 delete + 不作为自然淡出）。

### 5.3 组件二：PAR 有向联想检索（中游）
小节：
1. **跳转轴**：6×8 节点-边权重矩阵（附表格），方向性阻断（TAXONOMIC 正向=0），认知基础（扩散激活 [Collins & Loftus 1975] + 三条序数约束；对标 HippoRAG 的 Personalized PageRank [Gutiérrez 2024]）。
2. **目的回归**：目的推断（LLM，宽度=2 词）→ 目的向量 → 每步 `purpose_score` 过滤（阈值 0.2）与加权。
3. **峰值容忍带终止**：斜率寻峰 + 容忍带 δ=0.10 截段，替代固定 top-K；说明「伪峰值」问题。
4. **完整算法**：伪代码（Algorithm: PAR v2）。

### 5.4 组件三：StoryRank 故事化（下游表达）
- 三个职责：保留因果关系 / 前置整理避免污染聊天上下文 / 语义过滤。
- 机制：`expand_with_trace` → 连通性拆核心链路 → LLM 输出故事 + `adopted_ids`。

### 5.5 评测方法学重构（本次论文的方法论贡献，承 0908 §一 / §四）

> 承接 §3.2：旧 expected 标注模式在联想价值上系统性失效，本节给出替代范式。
> 方法学依据：LLM-as-judge [Zheng 2023]（judge-human 一致率 ~80%；position/verbosity/self-enhancement 偏置 → 驱动同题并排 + 多模型交叉 + 病态 judge 排除）。

1. **场景**：情感陪伴（系统基石）。
2. **评测对象**：系统喂给模型的结构化记忆上下文块——`{story}`/`{memories}`/`{entities,relations}`（不解耦回复 LLM 则变成比回复能力）。
3. **判断方式**：同题并排一次判定（相对比对，避免绝对打分天花板）。
4. **Rubric**：记忆丰富度 / 易理解性 / 用户建模度（各 1–5 分）。
5. **交叉一致性**：多模型独立判分（top-1 一致率 + Cohen κ + Spearman 秩相关），语言/文化偏差检测。
6. **成本口径**：内部 LLM token（写入/抽取侧 + 检索侧），嵌入模型与回复侧不计。

### 6.2 基线系统（对齐口径）
- **Ariadne**：PAR + StoryRank（tool-calling 按需检索）。
- **Mem0**（中文补丁：jieba + zh spaCy；向量+BM25 混合）。
- **Graphiti**（自托管 + Neo4j 5.26，时态图谱 + 三路混合检索，作为 Zep 核心对齐基线）。
- 公平性：同 embedding（bge-large-zh-v1.5）、同候选配额（D2 按 Ariadne N 对齐）、同批 judge。

### 6.3 指标
- 质量侧：judge 3 维 1–5 分（总均分 + 分情境 + 两两胜率）。
- 一致性侧：top-1 一致率、Cohen κ、Spearman 秩相关、区域（zh/en）均分差。
- 成本侧：单次写入 token、会话级 token、检索注入 token（cl100k 统一标尺）。

### 6.4 实现与环境（可复现）
- LLM（DBA/PAR/judge）、embedding（bge-large-zh-v1.5）、向量库（FAISS）、图引擎（NetworkX / Neo4j）。
- 关键：模型本地化、`HF_HUB_OFFLINE=1`、隔离依赖、版本化产物。

## 7. 实验结果（Results）

> 建议「先下游 e2e 定胜负，再上游消融归因」的叙事顺序（而非时间顺序），让读者先看到端到端结论，再理解机制。

### 7.1 端到端质量（主结论，承 0908 §3.2）
- 主判分总均分表：Ariadne 4.74 / Graphiti 3.63 / Mem0 2.99（3 维分解）。
- 按类别 total 均值表（8 类）。
- 两两对比：Ariadne vs Mem0 +1.74（64/2/4）、vs Graphiti +1.10（62/4/4）。
- 关键观察：易理解性最大分野（4.89 vs 2.29/2.73）；联想类达 4.86–4.89。

### 7.2 交叉一致性（承 0908 §3.2.4）
- 四模型排位表 + 两两一致性表。
- 结论：Ariadne 占优跨 4 模型稳健；同族 deepseek 反而给最低分（反证无自偏好）；glm-4-flash 形态偏好作废。

### 7.3 语言/文化偏差（承 0908 §3.2.5）
- 中文组 vs 国外组均分差表；结论：Ariadne 差仅 −0.04，无系统性语言偏差。

### 7.4 token 成本（承 0908 §3.3）
- 写入/抽取侧：单次写入恒定表（2.4k / ~9.2k / ~10.45k）。
- 会话级：~18k / ~58k / ~63k（Graphiti 用逐条 ingest 口径；冒烟实测 Graphiti ~41k 为 bulk 均摊，正文需二选一并注明）。
- 检索侧：候选数/注入量随规模表（Ariadne 恒 26 = 数据构造导致相关集合恒定，非「自然收敛」；Mem0 top_k=8 为 scale 实验默认值、非质量评测 D2 对齐；Graphiti facts 50→210 增长）。

### 7.5 上游建图质量与机制证据（承 0828 两篇）

> ⚠️ 口径：本节「DBA 抽取质量」属上游建图质量（gold 图对比），可作系统贡献；「PAR 消融 / 规模效应 / CROSS/LESS」属 0818–0825 检索层 expected 量化，**其数字不作跨系统结论**，仅作机制性内部证据（说明各组件做了什么）。

- **DBA 抽取（建图质量，可用）**：双重压缩（节点 43%、边 72%）→ 两步拆分 + 激进连边（节点召回 75–76%、边召回 34.8%、边类型一致 77.1%）。
- **PAR 消融（机制证据，不作排位）**：跳转轴=A2 归零、目的过滤 A4、目的加权 A5、TAXONOMIC 开放 A3——说明组件分工。
- **规模效应（机制证据，不作排位）**：PAR/A 比值随规模放大，仅说明图结构信号在大图上的行为。
- **行为三维度（机制证据）**：MORE / LESS / CROSS 描述 PAR 的行为特征。

## 8. 讨论（Discussion）

### 8.1 设计性质
- 跳转轴权重为手工设计（序数关系有理论支撑，精确值不可区分，`<0.02`）。
- LLM 原生架构随模型能力零成本增益；固定工程开销已优化到可忽略。

### 8.2 关键权衡
- PAR 的召回深度 vs 精确排序的取舍 → 适用「多轮陪伴提供丰富上下文」而非「精确排序」。
- token「恒定」≠「优势」：Ariadne 候选恒 26 是数据构造所致（相关集合恒定），Mem0 恒 8 是 top_k 截断——两者性质不同，不能同等视之。
- 图结构一致性要求低（边重合 34.8% 仍打平/反超），但**连通完整**必要。

### 8.3 局限（务必诚实列出）
1. 数据人工构造（无真实对话噪音）。
2. 单用户设计。
3. 小样本 + judge 主观判分方差（报告方向 + 区间）。
4. LLM API 波动主导延迟。
5. Mem0 图谱模块未启用（同源范式未实测）。
6. Graphiti ≠ 完整 Zep（缺 MMR rerank / context assembly）。

### 8.4 未来工作
- 真实对话日志泛化验证；多用户；统计显著性检验；更大规模 benchmark 接入（LoCoMo/MemoryAgentBench）。

## 9. 结论（Conclusion）
- 呼应贡献：三个组件 + 评测方法学重构 + 三系统对照结论。
- 核心启示：**在长期记忆检索中，「往哪个方向找、为什么找」比「找得多近」更重要。**
- 收束：从机制验证到生态效度评估是首要后续方向。

## 12. 撰写方法参考（来自检索的论文写作方法论）

> 以下要点提炼自系统评测 / 记忆评测 / RAG 评测类论文的通用写法，供正文写作时对照自查。

1. **IMRaD 骨架**：摘要—引言—相关工作—方法—实验设置—结果—讨论—结论—附录（AgentMemBench、Evaluating Long-Term Memory、RAG Playground 均如此）。
2. **评测论文三要素**：明确「评测对象 + 指标 + 基线」，并在实验设置里写清**对齐口径**（同数据/同查询/同指标/同判定/同 embedding），否则数字不可比。
3. **LLM-as-judge 要配交叉验证**：主观判分必须给多模型一致性（κ / Spearman / top-1 一致率），并披露同源偏置与病态 judge（本项目 glm-4-flash 即典型反例）。
4. **成本维度单列**：区分「内部 LLM token」与「回复侧/嵌入 token」，避免用单一质量指标下结论（AgentMemBench 将 Memory Footprint / Latency 与质量并列）。
5. **统计处理诚实**：小样本给「方向 + 区间」而非精确排位；R@all 类数字报告波动（本项目 std ±11.4pp 即为教训）。
6. **可复现性**：版本化数据/查询/产物 + 脚本固化 + 模型本地化，附录给数据卡片与复现清单。
7. **局限显式化**：人工构造数据、单用户、LLM 波动、范式未对齐等都要写进 Discussion，而非回避。

## 13. 写作顺序建议（Roadmap）

1. 先定标题 + 摘要（反复改）→ 锁死论点与贡献列表。
