## 摘要 Abstract（草稿，正式写作时定稿）

对话系统的长期记忆面临两个相互耦合的子问题：非结构化对话日志如何被持续转译为结构化图谱（上游建图），以及如何有方向、不偏离地从图谱中召回记忆（下游检索）。现有向量 / 图谱记忆系统普遍共享一个隐含假设——**关联强度 = 语义相似度或图距离**；这使召回行为天然偏向"语义相近"，却难以捕捉"功能相关"，并且无向的多跳扩展容易随跳数漂移，固定 top-K 截断则会错过深层跨域路径。

本文提出 Ariadne，一套 LLM 原生的对话记忆系统，其特性源于三个组件：① **LLM DBA**——把记忆图谱当作 LLM 自主维护的数据库（节点=主键、边=外键索引、LLM=DBA），以 CRUD 指令集 + 三层上下文 + 边衰减遗忘机制实现增量、可纠错、可持续的图谱维护；② **PAR（目的驱动的联想检索）**——以有向类型化的跳转轴（6×8 节点-边权重矩阵）约束扩展方向，用目的回归（LLM 推断目的向量 → 每步过滤与加权）表达"为什么找"，并以峰值容忍带（δ=0.10）替代固定 top-K；③ **StoryRank 故事化组装**——把候选因果链重组为可直接消费的叙事块。

在情感陪伴（系统基石）场景下，以**系统喂给模型的结构化记忆上下文块**为评测对象，经**同题并排一次判定 + 多模型交叉（qwen / deepseek / gemini / gpt）+ 匿名化消偏**，对 Ariadne 与 Mem0、Graphiti 做端到端对照。结果：Ariadne 质量 4.74 > Graphiti 3.63 > Mem0 2.99，且跨 4 模型稳健地列首位（易理解性为最大分野 4.89 vs 2.29 / 2.73）；在英文模型下匿名消偏后 Ariadne 仍居首，说明其占优主要来自内容形态（连贯叙事 / 因果链）。成本上，Ariadne 单次写入 ~2.4k、会话级 ~18k，均为三者最低且不随图规模增长（Mem0 ~9.2k / ~58k；Graphiti ~10.45k / ~63k；Graphiti 检索注入随规模 ~2× 增长，Ariadne 候选恒 26 为"目的约束下种子可达完备覆盖"，Mem0 恒 8 为 top-k 截断，二者性质不同）。

## 1 引言 Introduction

### 1.1 问题定义

长期记忆是对话系统从"瞬时反应"走向"持续陪伴"的关键。它包含两个相互依赖的子问题：**前置数据管理**（把非结构化对话日志持续转成结构化记忆图谱）与**在线检索**（从图谱中召回与当前情境相关的记忆）。

设想一个用户倾诉"最近压力太大"。一个理想的记忆系统应当沿着因果链唤起"加班 → 喝咖啡提神 → 拿铁 → 意大利咖啡文化"这一串记忆，从而给出有温度、有内在关联的陪伴；然而一个"按语义相似度召回"的系统，最容易命中"压力大"的字面近邻（如其它描述压力的句子），却无法自发地走向"功能相关"的缓解行为。这一例揭示了现有记忆系统的核心失效模式——**缺乏方向感**：它们知道"往哪条语义近邻找"，却不知道"为什么要往那个方向找"。

### 1.2 核心挑战

- **上游（建图）**：领域开放性（记忆覆盖生活方方面面）、长期可维护性（图谱随对话持续增长而不失控）、以及指代消解与省略补全（把口语化、有省略的第一人称倾诉，转化为独立可读、消解了指代的事实陈述）。
- **下游（检索）**：语义相似度 ≠ 功能相关；无向多跳扩展会在无关语义空间漂移；固定 top-K 会错过深层、跨域的路径。

**评测方法演进的动机（0818–0825 → 0908）**：早期我们曾采用 expected 字面标注模式（R@all / P@5 / expected 覆盖 / 带查询五维）量化系统。但该范式测的是"字面 / 语义命中人工预期节点"，天然偏纯向量，无法度量联想 / 发散区（cross-domain）的增值价值。一个关键反证是：同一系统在"带查询五维"下 P 指标落败，却在"纯故事 / 纯选择"范式下大幅反超（26:4 / 25:5）——换评判范式，结论方向即发生颠倒。因此，**0818–0825 的 expected 量化数据一律不作最终结论**，仅作为"评测方法缺陷"的动机素材；本文有效的质量结论，只看 0908 e2e 的四模型 judge 判分。

### 1.3 本文主张与贡献

1. **LLM DBA 架构**——记忆数据库模型 + CRUD 指令集 + 三层上下文 + 异步批量调度 + 边衰减遗忘。
2. **PAR 检索模型**——跳转轴（有向类型化权重矩阵）+ 目的回归（推断 / 过滤 / 加权）+ 峰值容忍带（替代固定 top-K）。
3. **组件维度分化的消融证据**——跳转轴主导召回深度、目的过滤主导召回-输出量权衡、目的加权主导精度微调（A2 / A4 / A5 因果证据）。
4. **StoryRank 故事化**——把候选因果链组装为可直接消费的故事块，提升可读性（其价值在"叙事链"而非"增加信息量"）。
5. **记忆系统评测方法学重构**——批判 expected 字面标注模式（在联想价值上系统性失效，故事二元化反转即证），提出"结构化记忆上下文块 + 同题并排 + 多模型 judge 交叉 + 匿名化消偏"新范式。
6. **三系统对照实证**——情感陪伴场景下，Ariadne 在质量（4 模型判分）与成本（单次 / 会话 LLM 最低）上优于 Mem0 / Graphiti。

### 1.4 论文组织

第 2 节回顾相关工作；第 3 节描述系统（三个组件 + 评测方法学）；第 4 节给出实验设置；第 5 节报告实验结果（先端到端定胜负，再上游消融归因）；第 6 节讨论设计性质、权衡与局限；第 7 节总结；附录给出复现性信息。

## 3 方法 Method

### 3.1 系统总览

```
对话日志 → LLM DBA（异步批量维护） → MemoryGraph + VectorStore → PAR 有向联想检索 → StoryRank 故事化 → 回复
```

三个组件上下游衔接：**图谱质量决定检索上限，检索候选决定故事化质量**。DBA 处于异步后台，每次对话后触发一次批量维护（平均 1 次 LLM 调用 / 批）。

### 3.2 组件一：LLM DBA（上游建图）

> 对标：主流文档知识图谱法（GraphRAG / LightRAG 一类，泛称）为一次性全量抽取；本文区别在 LLM **增量、可纠错**维护 + 遗忘机制。

**3.2.1 记忆数据库模型**：将记忆图谱类比为关系型数据库——**节点 = 主键**（一条独立可读的事实陈述），**边 = 外键索引**（LLM 自主决定的语义关联），**LLM = DBA**（数据库管理员，每次对话后异步执行一次维护操作）。CRUD 操作对应 create / update / fix_type / deprecate / create_edge / delete。模型不是一次性抽取器，而是持续维护这个数据库的 DBA；其核心优势是**增量可纠错**：节点类型标错 → 下轮 `fix_type` 修正；连错边 → `delete`；事实过时 → `deprecate` 标记失效（**非物理删除，保留历史可追溯**）。

**3.2.2 节点 / 边类型体系**

节点类型（6 种，按语义角色）：

| 类型 | 判定标准 | 示例 |
|------|---------|------|
| STATUS | 用户当前所处的客观状态 / 处境 | "用户最近压力很大" |
| REASON | 解释某状态 / 行为出现的原因 | "用户经常加班到晚上十点" |
| ACTION | 用户主动进行的行为 / 活动 | "用户靠喝咖啡提神" |
| THING | 具体的物品 / 地点 / 媒介 | "拿铁是用户最常点的咖啡" |
| PERSON | 与用户有社交关系的人 | "同事小王经常和用户一起加班" |
| EMOTION | 用户的主观情绪 / 感受 | "用户对加班感到疲惫" |

边类型（8 种，含方向性语义）：

| 类型 | 方向 | 判定 | 示例 |
|------|------|------|------|
| CAUSAL | 单向（因→果） | A 导致了 B | 加班→喝咖啡 |
| SCENARIO | 双向 | A、B 属于同一场景 / 环境 | 咖啡馆↔散步 |
| SEQUENCE | 单向（先→后） | A 发生后 B 接着发生 | 喝咖啡→散步 |
| PREFERENCE | 单向（人→对象） | 用户喜欢 / 偏好 B | 喝咖啡→拿铁 |
| SOCIAL | 双向 | A、B 涉及社交关系 | 用户↔同事 |
| ATTRIBUTE | 双向 | B 是 A 的属性 / 特征 | 公园↔安静 |
| TEMPORAL | 单向（事件→时间） | A 发生在 B 这个时间 | 面试→下周五 |
| TAXONOMIC | 单向（子→父） | A 是 B 的一种 / 子类 | 拿铁→咖啡 |

方向性汇总：**单向五类**（CAUSAL、SEQUENCE、PREFERENCE、TEMPORAL、TAXONOMIC，正反向权重差异）+ **双向三类**（SCENARIO、SOCIAL、ATTRIBUTE，正反向对称）。其中 **TAXONOMIC 正向（指向父类）在跳转轴被结构性阻断（权重=0）**，其检索价值在于把跨域联想从"概念漂移"约束为"功能等价"。

**3.2.3 三层上下文与维护判断**：三层上下文分别为**对话层**（本轮合并后的完整对话文本，用于理解意图、消解指代）、**记忆层**（向量检索 top-k 语义相关节点 + 它们之间的已有边，避免重复创建、发现矛盾触发 deprecate）、**结构层**（相关节点的一跳邻居 + 图谱统计摘要，感知操作影响范围、避免孤立节点）。**`k=15` 硬限制**（= `current_state_k`）与图谱总节点数完全解耦，因此 prompt 大小不随记忆增长而膨胀（216 节点图谱下三层 prompt 稳定在约 2,000 token）。

维护判断（LLM 返回空 ops 即跳过）：纯寒暄 / 打招呼、助手追问细节无新事实、延续话题无新信息、已覆盖 → 跳过；新事实、事实变化、矛盾、话题切换 → 需要维护。

**3.2.4 CRUD 指令集**（LLM 输出 JSON 指令）。节点操作 4 种：`create`（新建节点，content 为已消解指代、补全省略的完整陈述句）、`update`（更新已有节点，旧内容保留于 previous_content）、`fix_type`（修正之前标错的 node_type）、`deprecate`（标记失效，不物理删除）。边操作 2 种：`create`（新建边，只连有联想价值的）、`delete`（删除连错的边）。

System Prompt 编码的 7 条核心原则：只抽用户事实忽略共情寒暄；第一人称转"用户"、消解指代、补全省略；每条记忆独立可读；边不需要全连、只连有联想价值；不需要一次做对、错了下次修正；deprecate 后检查邻居重连线；发现矛盾时 deprecate 旧节点并新建。

**3.2.5 GraphBuilder：操作执行与校验**（纯工程逻辑，不调用 LLM）：

| 机制 | 说明 |
|------|------|
| 语义去重 | `create` 前向量检索（k=3），与已有节点余弦相似度 > 0.85 则跳过 |
| 类型校验 | NodeType / RelationType 双路径解析（先匹配枚举名、再匹配枚举值），纠正非标准类型名 |
| 跳转轴兼容性检查 | 创建边前检查 `get_jump_weight(from_type, rel_type, is_reverse)`，若权重 ≤ 0（如 TAXONOMIC 正向）则跳过建边（LLM 输出不合理边的最后防线） |
| 双向边自动补全 | SCENARIO / SOCIAL / ATTRIBUTE 创建正向边后自动补反向边 |
| 事务保护 | `_WriteTransaction` 追踪所有图变更；graph 写入成功但 vector_store 失败则回滚全部图变更（解决图谱-向量库不一致） |
| 孤立节点检测 | 每次维护后检查所有节点，入 / 出度均为零计为孤立；连续 3 次标记 `forgotten` 并从活跃图移除 |

**3.2.6 调度器（异步批量，限流而非加速）**，五层触发策略：

| 层 | 触发条件 |
|----|---------|
| 被动出口①：空闲超时 | 60s 无对话 → 触发 |
| 被动出口②：会话结束 | 会话结束 → 强制触发 |
| 主动出口①：DBA 累积判定 | 累积判定 3 次"需要维护" → 进入主动模式 |
| 主动出口②：批量上限 | 主动模式下缓冲区每积累 6 条 → 触发 |
| 自动跳过 | 连续 5 次空转（返回空 ops）→ 不再调用 LLM，直接清空缓冲区，零 LLM 调用 |

机制要点：**寒暄不累积**（判跳过的对话不计入 meaningful_count，不会推入主动模式）；单线程串行（`_flushing` 标志 + `_pending_flush` 队列）；daemon 线程主进程退出自动回收；停止时先触发最后一次维护再 `join`。**`M=6 批量`** 为生产默认值。

**3.2.7 遗忘机制（边衰减而非时间衰减）**：传统"N 天未访问 → 删除"在图中失效——节点只要连着几条边，跳转轴每轮扩展都会沿边走到它，`lastAccessedAt` 不断刷新、永不衰减。本文**将遗忘作用在边上**，由两机制驱动：

- **LLM 边审计（主动清理）**：每轮维护中 LLM 审计已有边，若某条边反映的关系已被新事实覆盖（PREFERENCE 改变、CAUSAL 被否定、SCENARIO 变更、指向已废弃节点），输出 `delete`。边审计在现有 LLM 调用中顺带完成，零额外成本（实测偏好改变场景正确删除 3 条过时边，零误删）。
- **LLM 不作为（自然淡出）**：相关记忆被反复连线，冷门话题不创建新边；旧边可能被 delete；节点边逐渐减少直至孤立 → 连续 3 次标记 `forgotten`。

强调：**LLM 不需要主动遗忘**——遗忘是它"不做什么"的结果（不为节点创建新边、不修复断掉的旧边）。该机制自调节、无需预设衰减天数，且与检索行为一致（节点"存在感"取决于能否通过联想路径到达）。

### 3.3 组件二：PAR 有向联想检索（中游）

**3.3.1 跳转轴（有向类型化权重矩阵）**。基于扩散激活理论（Spreading Activation）手工设计：激活沿语义网络连结扩散、强度随距离衰减；本文将其具体化为 6×8 节点-边类型权重矩阵（6 节点类型 × 8 边类型），并引入**目的回归**作为激活的约束信号。权重格式为"正向 / 反向"，`0` 表示阻断该方向。

| NodeType → | CAUSAL | SCENARIO | SEQUENCE | PREFERENCE | SOCIAL | ATTRIBUTE | TEMPORAL | TAXONOMIC |
|-----------|--------|----------|----------|------------|--------|-----------|----------|-----------|
| **STATUS** | 0.9/1.0 | 0.8/0.8 | 0.7/0.0 | 0.4/0.0 | 0.5/0.5 | 0.3/0.3 | 0.3/0.0 | **0.0/0.0** |
| **REASON** | 1.0/0.9 | 0.6/0.6 | 0.8/0.0 | 0.2/0.0 | 0.4/0.4 | 0.3/0.3 | 0.3/0.0 | 0.0/0.0 |
| **ACTION** | 0.9/0.7 | 0.8/0.8 | 0.9/0.6 | 0.5/0.0 | 0.6/0.6 | 0.4/0.4 | 0.5/0.0 | 0.0/**0.3** |
| **THING** | 0.3/0.3 | 1.0/1.0 | 0.4/0.4 | 0.8/0.0 | 0.3/0.3 | 0.7/0.7 | 0.3/0.0 | 0.0/**0.3** |

| **EMOTION** | 0.9/1.0 | 0.8/0.8 | 0.6/0.0 | 0.5/0.0 | 0.5/0.5 | 0.4/0.4 | 0.3/0.0 | 0.0/0.0 |

**方向性阻断原则**：每个跳转的方向必须与出发点有关。例如 STATUS 节点的正确扩展方向是原因（REVERSE_CAUSAL=1.0）、情境（SCENARIO=0.8）、后续行为（CAUSAL=0.9），而非分类学上位概念。**TAXONOMIC 正向（指向父类）权重为零是结构性阻断**——情绪 / 状态驱动的问题不应沿分类学关系漂移到无关上位概念；其反向（指向子类）对 ACTION / THING 节点开放 0.3，允许从父类检索具体子类实例。实证上，分类学扩散链在 47 / 63 / 83 / 216 节点的全部查询中零命中 Top-5。

**三条序数约束**（认知直觉）：① 因果关系的激活优先于情境关系（CAUSAL > SCENARIO）；② 情境关系优先于时序关系（SCENARIO > SEQUENCE）；③ 分类学关系在情绪 / 状态驱动联想中被抑制（TAXONOMIC = 0）。

**设计性质**：类型化权重的序数关系（0.9 vs 0.8 vs 0.7）有理论支撑，但**精确标定**在距离衰减与目的加权的双重压缩下差异极小（同序相邻数值实际综合得分差 < 0.02），几乎不可通过实验区分；其真实作用是**在不牺牲召回的前提下，为后续排序提供更细粒度的得分区分**（等权扩展 A1 在小图上输出反而更收敛，16.3 vs 18.9，说明类型化权重不是减少输出总量）。

**3.3.2 目的回归**。从用户当前消息推断隐含目的（轻量 LLM 调用）。例如「最近压力太大了」→ `purposes = ["倾诉", "缓解", "寻求安慰"]` → `目的向量 = embedding("倾诉 缓解 寻求安慰")`。**目的词宽度 = 2 词**为实验默认最优（dose-response 倒 U 曲线，过窄把所有缓解行为压缩到同一窄带、过宽失去过滤能力；此最优依赖数据集场景多样性，不可跨数据集泛化）。

每步校验：扩展一个候选记忆 `c` 时，`purpose_score = cosine(embedding(c), 目的向量)`；**`purpose_score < 0.2` → 丢弃**；最终得分 = `跳转轴权重 × 0.85^hop × 0.5 + purpose_score × 0.5`。阈值取 0.2 而非初始设计的 0.3，因为 bge-large-zh-v1.5 对"缓解"与"喝咖啡"的余弦相似度约在 0.2–0.3，0.3 会误杀大部分功能等价结果。

**3.3.3 峰值容忍带终止（替代固定 top-K）**。联想相关性**非单调**（先升、达峰、后降），固定 top-K 因此失效。初始设计的"寻峰后回到峰值单轮取候选"存在**伪峰值**缺陷：峰值轮几乎总是锁定在第 1 跳（种子轮用纯 purpose_score，量级 0.4–0.6；扩展轮引入 jump_weight 加分后均值必然跳涨，形成伪峰值），导致**所有距离种子 2 跳以上的节点永远被丢弃**。修正为**峰值容忍带截段**：收集均值在 `[peak_μ − δ, peak_μ]` 范围内的**所有轮次**候选（去重），**容忍常数 δ = 0.10**。

示例轨迹（216 节点"工作压力大怎么放松"）：

```
Hop 0  seed         μ=0.557  ← 仅 purpose_score
Hop 1  跳转轴扩展    μ=0.861  ↑ 峰值（jump_weight 首次引入）
Hop 2  跳转轴扩展    μ=0.820  → 距峰 δ=0.041 < 0.10 → 纳入容忍带
Hop 3  跳转轴扩展    μ=0.798  → 距峰 δ=0.063 < 0.10 → 纳入容忍带
Hop 4  跳转轴扩展    μ=0.738  → 距峰 δ=0.123 > 0.10 → 截断
```

δ 敏感性：δ=0.05 过严（216 节点 R@all 降至 0.500）；δ=0.15–0.20 输出量增加 15–58% 但 R@all 边际仅 +0.003–0.007；**δ=0.10 为 R@all-输出量 Pareto 最优点**。CROSS 案例（"工作压力大怎么放松"，9 个期望记忆跨四域）验证其独立贡献：寻峰 Hop1 锁死丢弃深跳节点，容忍带截段后 R@all 从 0.556 提升至 0.667。

**3.3.4 完整算法（PAR v2）**

```
Algorithm: Purpose-Driven Associative Retrieval (v2)
Input:  用户查询 q
Output: 容忍带内的候选记忆集 R

1.  status, purposes ← InferStatus(q)
2.  purpose_vec ← Embed(purposes)
3.  M₀ ← VectorSearch(q, k)
4.  μ₀ ← mean(purpose_score(M₀, purpose_vec))
5.  seen_peak ← False, extra_rounds ← 0

6.  for hop = 1 to max_hops:
7.    C ← Expand(M_{hop-1}, jump_axis_rules)
8.    C ← filter(C, purpose_score > 0.2)
9.    C ← C × 0.85^hop × 0.5 + purpose_score × 0.5
10.   μ_hop ← mean(combined_score(C))

11.   if |μ_hop - μ_{hop-1}| < 0.015:   // 持平
12.     M_hop ← C; continue
13.   if μ_hop > μ_{hop-1}:             // 上升
14.     seen_peak ← True; peak_hop ← hop; peak_μ ← μ_hop
15.     extra_rounds ← 0
16.     M_hop ← C
17.   else:                             // 下降
18.     extra_rounds++
19.     if seen_peak and extra_rounds > 2:
20.       // 峰值容忍带截段（替代点峰值）
21.       for each hop h:
22.         if μ_h ≥ peak_μ - 0.10:
23.           R ← R ∪ candidates_h (去重)
24.       return R
25.     M_hop ← C

26. // 未触发寻峰（如首跳即低于种子）：退回全局峰值 + 容忍带截段
27. if not seen_peak:
28.   peak_μ ← max(μ_0, ..., μ_{max_hops})
29.   for each hop h:
30.     if μ_h ≥ peak_μ - 0.10:
31.       R ← R ∪ candidates_h (去重)
32. return R
```

主要超参：`seed_k=5`、`max_hops=5`、`purpose_filter_threshold=0.2`、`jump_weight:purpose_weight = 0.5:0.5`、`patience=2`、`min_delta=0.015`、`peak_tolerance=0.10`、`distance_decay=0.85`。

### 3.4 组件三：StoryRank 故事化（下游表达）

三个职责：**保留因果关系**、**前置整理以避免污染聊天上下文**、**语义过滤**。机制：基于 `expand_with_trace` 记录逐步扩展轨迹 → 按连通性拆出核心因果链 → 由 LLM 输出一段故事 + `adopted_ids`（明确采纳哪些候选）。

关联到评测：Ariadne 的上下文块形态即为 `{story}`（唯一走故事化表达的系统）。消融显示（见 §5.4，0908 §3.4），故事化的核心价值是**把同一批候选重组成更易直接消费的叙事链**——其增量几乎全部落在"易理解性"（+1.0~+1.8），而记忆丰富度 / 用户建模度（信息量维度）几乎不动；同时提升判分一致性（kappa 0.25→0.39，top-1 0.48→0.73）。

### 3.5 评测方法学重构（本次论文的方法论贡献）

> 承接 §1.2：旧 expected 标注模式在联想价值上系统性失效，本节给出替代范式。方法学依据：LLM-as-judge [Zheng 2023]（judge-human 一致率 ~80%；position / verbosity / self-enhancement 偏置 → 驱动同题并排 + 多模型交叉 + 病态 judge 排除）。

1. **场景**：情感陪伴（系统基石）。
2. **评测对象**：系统喂给模型的结构化记忆上下文块——`{story}` / `{memories}` / `{entities,relations}`（不解耦回复 LLM 则会退化为比较回复能力）。
3. **判断方式**：同题并排一次判定（三系统上下文块同题一起交 judge，相对比对，避免绝对打分天花板）。
4. **Rubric（3 维各 1–5 分）**：记忆丰富度 / 易理解性 / 用户建模度。
5. **交叉一致性**：多模型独立判分（top-1 一致率 + Cohen κ + Spearman 秩相关），语言 / 文化偏差检测，并叠加**匿名化消偏**（把系统匿名化为 A/B/C，随机打乱对应关系，检验/消除名称与维度偏好，见 §四 / 0908 §四）。
6. **成本口径**：内部 LLM token（写入 / 抽取侧 + 检索侧），嵌入模型与回复侧不计。

### 5.4 token 成本（承 0908 §3.3）

| 系统 | 单次写入（LLM token，随规模） | 会话级（6 轮+1 换话题） | 检索注入（随规模） | 检索侧 LLM | 检索完整性 |
|------|:---:|:---:|:---:|:---:|:---:|
| **Ariadne** | **2394（恒定，最低）** | **~18k（最低）** | 故事 ~330–420 token（恒定，候选 26） | search=2 次 | **完备覆盖（种子可达 + 目的约束内完整）** |
| Mem0 | ~9230–10175（恒定） | ~58k | 8 条 / ~217–267 token（scale 默认 top_k=8） | 0（非 LLM） | 受限（scale 截断损失；质量评测已 D2 对齐 Ariadne N） |
| Graphiti | ~10419–10524（恒定） | ~63k | facts 50→210 / token 888→3635（**随规模 ≈2× 增长**） | 0（非 LLM） | 随规模放大 |

**关键机制解释**：

- **Ariadne 候选恒 26**——归因于"图结构 + 目的约束下的种子可达完备性"，而非笼统的"机制自然收敛"：从起点种子出发、在目的回归 / 约束内可达的因果链节点集合恰好为 26；图规模 50→200 时新增节点并不在该查询种子的可达因果链上，故候选数恒定。它是"该查询目的约束下、种子可达集的完备覆盖"（不遗漏、不膨胀），**不是**"检索器随意封顶"，也**不是**"随图规模自适应收敛"。
- **Mem0 返回恒 8** = 检索侧 scale 实验默认 `top_k=8`（未对齐 Ariadne 配额）。库内可能有更多相关记忆但只取前 8，代价是检索深度 / 丰富度下降，且库越大被砍掉的潜在相关记忆越多（该损失不体现在 token 数里）。**注意**：这是 §5.4 检索侧实验（暴露规模趋势）的设定；在质量评测（§5.1）里 Mem0 / Graphiti 已 D2 同配额对齐到 Ariadne 的 N，并非恒 8。
- **Graphiti 返回 facts 50→210（随规模增长）**：检索侧设 `limit=4096` 不人为截断，暴露图遍历返回的子图规模随图膨胀——它是三者中唯一"检索注入随规模放大"的。

→ 综上，Ariadne 的"恒 26"（种子可达完备）与 Mem0 的"恒 8"（scale 默认 top_k 截断）**性质不同**，与 Graphiti 的"随规模增长"（图遍历放大）三者口径各异；跨表对比时**不可把"恒定"混为一谈**。

**单次写入（随规模）明细**：Ariadne 2394（恒定）；Mem0 9230→9055→10175（平 ~9.2k）；Graphiti 10419→10451→10524（平 ~10.45k）。

**检索侧（注入量 vs 完整性）明细**：Ariadne 候选数 26（恒定）、故事注入 415→331→367（~330–420）、检索 LLM 1773→2111→1733（~1.7–2.1k）；Mem0 返回 8 条（top_k=8 截断）、注入 217→245→267（~217–267）、检索 LLM 0；Graphiti 返回 facts 50→102→210（≈2×）、注入 888→1785→3635（≈2×）、检索 LLM 0。

### 5.5 判分可靠性：匿名化消偏与名称 / 维度偏好（承 0908 §四）

这是本文判分方法学贡献的核心，独立于主判分。

**设计**：三系统对照打分 1–5 总分 + 排名，叠加两个提示词变量——**匿名化**（三系统匿名为 A/B/C，每条查询用固定种子随机打乱对应关系，避免位置偏好）；**取消三维明细**（只打整体总分 + 一句总体短评）。设「不匿名 + 取消三维」与「匿名 + 取消三维」对照，把匿名化与取消三维拆开。

**结果①（三系统总分均，同模型分"三维明细 / 不匿名+取消三维 / 匿名+取消三维"）**：qwen 4.74 / 4.69 / 4.41；deepseek 4.17 / 4.33 / 3.77；gemini 4.56 / 4.54 / 4.50；gpt 4.43 / 4.26 / 4.24。

**结果②（匿名效应 |匿名 − 不匿名|，同"取消三维"口径，Ariadne）**：qwen 0.28（中文模型，名称反应明显）；deepseek 0.56（名称反应最明显）；gemini 0.04（几乎无）；gpt 0.02（几乎无）。

**结果③**：匿名（纯内容）下 Ariadne 仍居首（qwen 4.41 / deepseek 3.77 / gemini 4.50 / gpt 4.24，四模型均第一）；匿名 vs 带名 top-1 一致率 qwen 81.4% / deepseek 54.3% / gemini 85.7% / gpt 67.1%。

**结果④（中文模型名称反应两次复测稳定性）**：qwen seed42 +0.27、seed7 +0.31（差 0.04）；deepseek +0.56、+0.49（差 0.07）。→ 名称反应是可复现的系统性偏置，幅度稳定，deepseek 比 qwen 更敏感。

**结论**：
1. 名称反应只存在于中文模型（qwen +0.27~+0.31、deepseek +0.49~+0.56）；英文模型（gemini 0.04、gpt 0.02）几乎无差。
2. **"知名度"假说被否定**：若名称光环来自知名度，更认识 Mem0 / Graphiti 的 gpt / gemini 应在不匿名时抬 Mem0 / Graphiti；但实测匿名后反而略升或持平。→ 名称光环不是知名度，而是中文模型对"Ariadne"名称的正向先验。
3. 取消三维影响很小（各模型差均小于各自的匿名效应）。
4. **Ariadne 占优在"纯内容 + 跨模型"下仍稳健**：英文模型匿名下 Ariadne 仍最高，且它们对名称无偏置 → 占优主要来自内容形态（连贯叙事 / 因果链），而非名称。
5. 判分应优先采用匿名 + 跨 zh/en 多模型；"Ariadne 占优"在纯内容判断下成立，幅度以匿名 + 英文模型视野更可信。

> **短评佐证（形态偏好）**：即使匿名，qwen 短评绝大多数明确偏好"连贯叙事 + 因果链 + 完整背景"（对应 Ariadne 故事化形态），并批评其它块"碎片化 / 罗列 / 平铺直叙 / 偏离主题"；少数条赞赏"结构化关系 / 因果链条"（对应 Graphiti 形态）→ 判分偏好来自**内容形态**本身，而非系统名称。

## 6 讨论 Discussion

### 6.1 设计性质

- 跳转轴权重为**手工设计**：序数关系（0.9 vs 0.8 vs 0.7）有理论支撑，但精确值不可区分（同序相邻差异 < 0.02）。
- **LLM 原生架构随模型能力零成本增益**；固定工程开销已优化到可忽略（三层 prompt 稳定 ~2k，与图规模解耦）。
- 判分方法学（匿名 + 多模型 + 并排）与结果披露（方向 + 区间）是质量结论可信的基石。

### 6.2 关键权衡

- **PAR 的召回深度 vs 精确排序**：PAR 更适用"多轮陪伴提供丰富上下文"，而非"精确排序"（其 R@all 高但 P@5 不占优）。类比：Graphiti / Mem0 更接近"精确检索"，Ariadne 更接近"启发式联想供给"。
- **token"恒定"≠"优势"**：Ariadne 候选恒 26 是**数据构造所致**（相关集合恒定），Mem0 恒 8 是 **top_k 截断**——两者性质不同，不能同等视之。
- **图结构一致性要求低但连通完整必要**：边重合仅 34.8% 仍可打平 / 反超（gold 子图不是最优图）；但"完整性仍必要"——边不是"连对"而是"有边可走"（激进连边 170 条保证联想路径不断）；边覆盖提升 ≠ 检索提升（第二轮迷宫连边激进 965 条，检索收益仅 +3.7pp）。

### 6.3 局限（务必诚实列出）

1. 数据人工构造（无真实对话噪声）。
2. 单用户设计。
3. 小样本 + judge 主观判分方差（报告方向 + 区间；判分跨次 std ≤0.06，真正方差来自换模型）。
4. LLM API 波动主导延迟。
5. Mem0 图谱模块未启用（同源范式未实测，但核心结论不受影响）。
6. Graphiti ≠ 完整 Zep（缺 MMR rerank / context assembly / 托管设施）。

### 6.4 未来工作

- 真实对话日志泛化验证；多用户；统计显著性检验（小样本 → 方向 + 区间仅作过渡）；更大规模 benchmark 接入（LoCoMo / MemoryAgentBench）；判分匿名化纳入主判分流程（而非独立子实验）。

## 7 结论 Conclusion

本文提出 Ariadne——一套 LLM 原生对话记忆系统，由 LLM DBA（上游建图）、PAR（有向联想检索）、StoryRank（故事化组装）三组件构成，并将其置于情感陪伴场景下、以"结构化记忆上下文块"为对象的端到端评测中，与 Mem0、Graphiti 对照。在质量（4 模型判分，Ariadne 4.74 > Graphiti 3.63 > Mem0 2.99，跨模型稳健，英文模型匿名消偏后仍居首）与成本（单次 / 会话 LLM 最低且不随图规模增长）上均占优。

核心启示：**在长期记忆检索中，"往哪个方向找、为什么找"比"找得多近"更重要**。目的驱动的有向联想检索 + 故事化表达的可读性，构成了 Ariadne 相对纯向量 / 图记忆系统（Mem0 / Graphiti）的结构性优势。从机制验证走向生态效度（真实对话、多用户、大规模 benchmark）评估，是首要后续方向。
