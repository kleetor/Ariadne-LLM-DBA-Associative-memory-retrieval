# 人称归属与时序链路修复报告（0911）

> 范围：MCP 链路（ALM 侧未改动）。本文汇总本轮"人称归属"与"时序"两条线的工作、实测证据与遗留问题。

---

## 一、人称归属

### 1.1 问题来源

来自 txt 日志反馈：**"每一条节点都出现「用户」二字"**。在群聊场景下，不同说话人的事实被一律并入"用户"，导致归属塌缩。

### 1.2 根因定位

抽取提示词里的 content 规则原本使用**绝对代称**（一律转成「用户」），在单人对话题材下成立，多人对话下即失效。

### 1.3 改动

| 位置 | 改动 |
|---|---|
| [`NODE_EXTRACTION_PROMPT` 原则 3](../dba_pipeline/extraction/dba.py) | 改为**按对话形态分流**：单人对话 → 对话方转「用户」、助手自身转「助手」；多人对话 → 各人按其姓名/昵称归属（如「阿哲最近在赶设计稿」），明确"不得把其他人一律并入「用户」" |
| [`dba_add_conversation` 字段描述](../dba_pipeline/mcp_server.py) | 补充"多人对话请保留说话人标识（如「[阿哲] 我最近压力挺大」），否则无法区分事实归属；单人对话无需标识" |

### 1.4 实测结果

**群聊专项**（8 行、3 说话人、带 `[昵称]` 标识），抽取 16~18 个节点：

```
归属词频（节点内容中出现的次数）: {'阿哲': 3~5, '小林': 3, '老周': 2~3, '用户': 0}
```

- 带方括号标识 → **「用户」出现 0 次**，各人事实按昵称落地。
- txt 日志那份输入是**自然叙述、无方括号标识**，因此仍大量写成"用户"。

### 1.5 结论与遗留

- **归属质量取决于输入是否带说话人标识**，当前只是软约束（提示词 + 工具描述），无程序化保障。
- 已在 Plan §6.4 记录：ALM 侧另有一类"视角污染"（同 `user_id` 下 9 节点中 5 个属对话对方，被标成"助手…"），依赖平台的 role 映射方式，属待与主办方确认项。

## 二、时序链路

### 2.1 出发点

txt 日志指出两个问题：

1. **回退裸奔**：「8月30日」若库中无该时段节点，语义检索会返回「8月1日」等邻近锚点，且**没有任何"这是回退"的信号**，上层会很有信心地把 8/30 的事当成 9/7 讲出去。
2. **节点没有时间戳字段**，且 `update_node` 只能改 `content`/`node_type`，存量节点补不了时间。
3. 另有"锚点基数只有 1 个（n5）"——只有 1 个锚点时，"最相似"是恒等函数。

### 2.2 改动清单

#### (a) 节点时间戳通道（端到端贯通）

| 层 | 改动 |
|---|---|
| 登记通道 | [`PERSISTED_NODE_FIELDS = ("speaker", "timestamp")`](../dba_pipeline/graph/memory_graph.py)，`to_dict` / `from_dict` 自动透传 |
| 写入 | [`GraphBuilder.apply_ops(batch_timestamp=)`](../dba_pipeline/extraction/graph_builder.py) → `_create_node` 写入节点 |
| **读回（关键断点）** | [`loader.load_graph()`](../dba_pipeline/loader.py) 与 `load_multi_graph()` 回填扩展字段——此前保存走 `to_dict`、载入走另一套代码，字段落盘即丢 |
| ALM 写入侧 | `MemorySpace.add()` 取批次末条消息时间戳注入；兜底落库同样带上 |
| MCP 写入侧 | `add_conversation` 直连路径按落库时刻注入；**调度器路径见 (b)** |

#### (b) 调度器批量路径：每轮到达时间进入抽取输入

调度器 `_buffer` 原本是 `List[str]`，入队即丢时间。改为 `List[Tuple[Optional[int], str]]`：

- (b-1) 合并文本时给每轮加前缀 `[YYYY-MM-DD HH:MM:SS]`（精确到秒——一批最多跨 `idle_timeout` 90s，只到分钟会把各轮压成同一个串）
- (b-2) 节点时间戳取本批**最后一轮**到达时间
- (b-3) `save_state` / `load_state` 序列化 `[[ts, text], ...]`，**兼容旧格式**（纯文本 → ts=None）

> 参照：ALM 侧 `_format_conversation` 本就在做同样的事（`[role@timestamp] content`），MCP 侧是唯一丢时间的。

#### (c) 时序工具：从"无校验"到"三级校验 + 显式信号"

| 改动 | 说明 |
|---|---|
| `_EXPLICIT_PERIOD_RE` 顺序修正 | 「周X」提到裸「上周/这周」之前。原顺序下「上周三」被拆成「上周」，会与库中「上周五」锚点**误判为同一时期** |
| 新增 `_FUZZY_PERIOD_RULES` | 模糊时期词 → 可接受锚点集合，**按该词的时间跨度划线**：「前几天」不含一周前的「上周三」，「这两天」不含上周，而「最近」「那天」跨度大允许覆盖上周 |
| 校验三级 | 显式词硬校验字面命中 / 模糊词按映射集合软校验 / 无时间词不校验 |
| 新增返回字段 | `match_type`：`exact` \| `fuzzy` \| `fallback` \| `rejected`；`rejected` 时附 `reason` |
| `TOOL_TIME_ANCHOR_RE` 补模糊时期词 | 修掉"锚点存在却定位不到"——LLM 会把「前几天」抽成 THING 锚点，但白名单没有它，于是 `_tool_is_time_node` 判否 |
| MCP 拒答 note 分支 | `rejected` 时不再引导"改用 dba_query_memory"，改为说明"这是拒答、不是检索失败；不要拿其他时段顶替" |
| 工具描述同步 | `dba_temporal_lookup` 写明 `match_type` 四档语义与 `rejected` 时的回话要求（此前字段有了但描述没写，接入方读不到） |

#### (d) 记录时间渲染（MCP 开、ALM 关）

| 改动 | 说明 |
|---|---|
| `format_ts_ms()` | Unix 毫秒 → 本地日期 |
| `_build_path` | 节点 dict 附加 `timestamp`（附加字段，不开启渲染就不进 prompt） |
| `retrieve_with_story(render_timestamps=False)` | 默认关闭 |
| `story_rank(render_timestamps=False)` | prompt 拆为 `STORY_RANK_PROMPT`（逐字不变）/ `STORY_RANK_PROMPT_TS`（追加规则 9：**「记录于」是记录时间，不是事件发生时间**） |
| `dba_query_memory` | 显式开启 `render_timestamps=True` |

### 2.3 实测证据

**（1）时间戳端到端贯通**（`eval/test_timestamp_chain.py`）

```
① 注入   7/7 节点 ts=1789115040247（落在调用窗口内）
② 落盘   缺 timestamp 的节点：无
③ 重载   load_graph 后 7/7 一致
④ 拒答   「2025年1月1日」→ rejected=True, count=0
⑤ 命中   锚点 n6「2026年9月7日」→ n7
```

**（2）模糊时序收紧**（同一查询「前几天群里聊了什么？」）

| 阶段 | 结果 |
|---|---|
| 改前（无校验） | count=2，锚点「前天」+「**这周二**」——纯语义混入，无信号 |
| 模糊映射 v1（含"上周"） | count=2，锚点「上周三」+「上周五」——映射过松 |
| 收紧后 | **count=1，只剩「前天」** |

**（3）显式日期精确化**：「上周三开会定了什么？」由"命中上周三但**带出上周五**"变为 `match_type=exact`，只返回本周三锚点。

**（4）调度器批量路径**（8 轮独立入队 → 一次维护）

```
已入队 8 轮，缓冲区=8
维护后: 18 节点 / 89 边
时间前缀泄漏进节点内容: 无        ← 关键：LLM 正确把方括号当元信息丢弃
节点时间戳取值集合: [1789123638530]   ← 批次级
```

**（5）回归**：`eval/test_mcp_link.py` 通过——锚点 `['T10']`、共时事实 `{e9,e10,e12}` 与改动前一致。

### 2.4 时序遗留项的处理结果

| 项 | 说明 |
|---|---|
| `timestamp` 是**批次级** | 抽取不产出"节点↔轮次"归属，无法逐轮回填。当前默认配置下一批最多跨 90s、最多 10 轮，批次级与轮次级差距有限；每轮的精确时间已通过文本前缀进入抽取输入 |
| `timestamp` 是**记录时间** | 不是事件发生时间。文本里说"上周三"、时间戳记的是"今天"，两者语义不同，已在 prompt 规则 9 与工具描述中显式区分 |
| 词表不同步 | **已修**：时期词集中为单一来源，分四类（绝对硬校验 / 模糊软校验 / 人生阶段软校验 / 仅锚点）；新增「今天/上个月/这个月/下个月/上学期/下学期」进硬校验，新增「人生阶段」软校验类；并把「最近/近来/这段时间」**移出校验**（跨度过大，误判成"无该时段记录"的提示是错的）。覆盖情况由 `eval/test_timestamp_chain.py` 的 ⓪ 检查兜底 |
| `has_temporal_signal` 门控 | **实测结论：不需要改，改了有害。** 在 41 条带 `temporal` 标注的评测对话（`data/dba_eval/*_dialogs.yaml`）上：现有门控（≥2 个不同具体日期词）正例触发 **30/30**、负例误触发 **0/11**；把模糊词（前几天/最近/那天/后来…）并入门控后，正例仍为 **30/30（零收益）**，而负例误触发升到 **8/11（+8）**。"纯模糊时序会话无锚点"在真实语料上不成立，属理论担忧 |
| `dba_intervene` 不支持 `timestamp` | **已修**：`update_node` 与 `create_node` 均支持 `timestamp`（Unix 毫秒，`null` 可清空） |
| 锚点依赖 LLM 产出的 TEMPORAL 边 | **部分兜底**：返回的每条事实新增 `time_consistent`（`false` = 事实自带时期词与锚点完全不相交，疑似连边错配；`null` = 无法判定）。只打标不删除；**同区间内挂错事件（如把别的「前天」事件挂到「前几天」上）仍抓不到**，那需要 source 层 |
| 人工建节点绕过去重 | **已修**：`create_node` 命中完全相同的既有内容时拒绝创建并返回 `duplicate_of`；仅语义高度相似时创建成功但附 `duplicate_warning`（**不据此拒绝**——日期锚点这类短内容在向量空间里彼此极相似，按余弦拒绝会挡住合法的锚点建设） |

## 三、附带修复（StoryRank 叙事质量）

时序排查过程中顺带发现并修复了叙事层的问题：

| 改动 | 效果 |
|---|---|
| prompt 加"因果克制"（仅 CAUSAL 边可用因果词） | 不再把并列关系缝成因果 |
| prompt 加"主体不能串" | 「谁在抱怨加班？」中"客户换主色让小林加班"的跨主体串味消失 |
| prompt 加第 8 条：`adopted_ids` 必须与正文严格对应 | 一致性告警 0 项（此前出现过"结论节点被判 discarded、正文却写了结论"） |

实测：「谁在抱怨加班？」采纳节点从 **14 → 2~5**，故事由 200+ 字收敛为一句话。

## 四、遗留问题总览

| 项 | 状态 |
|---|---|
| `dba_intervene` 不支持 `timestamp`（存量补不了） | ✅ 已修（`update_node` / `create_node` 均支持，`null` 可清空） |
| `intervene.create_node` 不走去重（txt 的 n25/n27 重复 person 直接成因） | ✅ 已修（完全相同 → 拒绝并给 `duplicate_of`；语义疑似 → 创建但附 `duplicate_warning`） |
| 词表不同步（今天/上个月/当天/大二上学期） | ✅ 已修（集中为单一来源 + 四类划分 + ⓪ 覆盖检查） |
| 锚点依赖 TEMPORAL 边、错配无兜底 | ⚠️ 部分兜底（`time_consistent` 打标；同区间内错配仍抓不到） |
| `has_temporal_signal` 门控（纯模糊时序无锚点） | ✅ 已评估：**不改**（正例 30/30 零收益、负例误触发 0/11→8/11） |
| 锚点基数低 | ⬜ 数据/抽取决定，非代码可修 |
| 抽取结果不可复现（同一输入节点数 16~18 浮动） | ⬜ 未动，影响后续任何调优的可归因性 |
| 推测写成事实（n22），不可证伪、无纠正环节 | ⬜ 未动，需 source 层 + 巡检 |
| 相对时间表述（「过两天」）独立成锚点会漂 | ⬜ 未动，需相对时间归一化 |
| `timestamp` 无消费方（ALM 侧仍只写不读） | ⬜ 未动，ALM 本轮冻结 |
| `speaker` 字段已登记但从未写入 | ⬜ 未动（预留通道） |

### 遗留项对应的测试资产

- **⓪ 时期词覆盖检查**（离线、确定性）：`eval/test_timestamp_chain.py` ⓪ 段。用一份外部维护的已知词表做不变量断言——凡能被锚点识别的时期词，要么进入校验（explicit/fuzzy/era），要么在文档化的"仅锚点"例外清单里；并断言「工作/毕业/晚上」等非时间语境词**不得**进入硬校验、年份不得进入硬校验。
- **T3 一致性打标**：`eval/test_mcp_groupchat.py` ③ 段打印每条事实的 `time_consistent`。

> 剩余未动的四项（推测写成事实 / 重复节点残余 / 抽取不可复现 / 相对时间漂移）共同根源是**缺少 source 层**，另见新计划文档。
