## 二、接口

### 2.1 端点

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/add` | 需要 | 同步写入记忆 |
| POST | `/search` | 需要 | 同步检索记忆证据 |
| GET | `/health` | **免鉴权** | 轻量探活，返回 HTTP 200 |

- 公网地址：`https://alm.ariadne.top`（HTTPS；URL 内不含任何凭据）
- 实际监听端口与反向代理拓扑由我方维护，平台只需按上述公网地址调用

### 2.2 鉴权

- 支持 `X-Api-Key: <key>` 与 `Authorization: Bearer <key>` / `Authorization: Token <key>`
- Memory System Key 由我方生成并保管，**通过平台受控提交流程提供**，不写入本文件、
  仓库、URL、截图或邮件正文
- 未携带或无效凭据返回 `401`；错误体统一为 `{"detail": {"reason": "..."}}`

### 2.3 契约一致性

| 契约要求 | 本系统行为 |
|---|---|
| Add 同步：落库且可立即检索后才返回 200 | 请求内完成记忆维护与索引落盘后才响应 |
| Add 响应原样回显 `request_id` / `user_id` / `session_id`，`success` 为布尔 `true` | 一致；三个 ID 逐字节回显 |
| 不使用 `metadata` / `app_id` / `agent_id` / `async_mode` | 一致 |
| 禁止 202 / task ID / 状态查询地址 | 不使用异步语义，无 Add-status 端点 |
| Search 请求字段 `query` / `options`? / `user_id` / `top_k` | 一致；`options`（选择题）接受并校验，**不用于生成答案** |
| Search 响应为顶层 `data` 数组，元素含必填 `id` / `content`，可选 `score` | 一致；不返回 `items` 包裹层，未声明字段不输出 |
| 元素可含可选 `created_at` | 一致：原子节点返回 `created_at`（`YYYY-MM-DD`，取节点记录时间）；无时间戳的节点不输出该字段。**叙述条目刻意不带**——它跨多条记忆，给单一日期会误导时间判断 |
| 无相关记忆时返回 `[]`（不省略 `data`） | 一致 |
| 条数不超过 `top_k`（正式评测 100） | 一致 |
| `user_id` 为唯一检索隔离域 | 一致：每个 `user_id` 一份独立图谱与独立向量索引，结构上不可能跨用户召回 |
| `session_id` 不作为检索过滤 | 一致：仅回显 |
| `content` 为检索到的记忆本身，不含针对当前 query 推导出的最终答案 | 一致：返回「记忆叙述 + 原子记忆节点」，叙述仅整理已检索记忆 |

**说明**：Add 单次请求处理的消息上限为 64 条、兜底落库上限 256 条，均高于平台切分口径
（≤20 条消息 / ≤2000 词），不会触发截断。

## 三、运行与运维

| 项 | 做法 |
|---|---|
| 部署形态 | 单实例容器（`Dockerfile.alm` + `docker-compose.alm.yml` + `.env.alm`），进程常驻 |
| 常驻 | `restart: unless-stopped`；**评测期内不主动重建或迁移实例** |
| 持久化 | 记忆落盘于容器内 `/data`（**每个 user_id 一个目录**，目录内是 `graph.yaml` / `graph.index/` / `docs.yaml` / `docs.log` / `docs.index/`），挂命名卷；容器重启、镜像升级均不丢数据 |
| 健康检查 | 镜像内置 `HEALTHCHECK` 打 `/health`；平台探活路径同上 |
| 日志 | 仅记录数值、计数与掩码后的 `user_id`（如 `eval***nv-0`）；**不记录记忆正文与 query 正文** |
| 出网依赖 | 需要访问 LLM 与 embedding 端点；无入站依赖（除平台调用） |

### 3.1 所需环境变量（由我方在部署环境注入）

```
OPENAI_MODEL=deepseek-v4-flash    # 工业榜对 Add / Search 使用的模型无限制；即我方实际所用模型
OPENAI_API_KEY=...                # 我方自有凭据
OPENAI_API_BASE=https://...       # 我方自选端点
EMBEDDING_MODEL=BAAI/bge-m3        # 必须与 EMBEDDING_API_BASE 端点上的模型名一致
EMBEDDING_API_KEY=...                   # （换供应商需同步改；填错时 Search 返回 5xx 由平台重试，
EMBEDDING_API_BASE=https://...          #   不会静默返回空数组）
EMBEDDING_LOCAL=false             # 容器一律走 API embedding（无 GPU，镜像不预置本地模型）
ALM_API_KEYS=<Memory System Key>  # 公网部署必须非空——为空时服务**拒绝启动**，不是放行请求
ALM_LLM_THINKING=0                # 关闭链路内部 LLM 的思考模式（实测省约 94% output token，
                                  # 质量无显著差异；见 Plan/alm/0921——thinking档位对照实验报告.md）
ALM_DATA_DIR=/data

# 余弦阈值（v0.1.5-alm 起，随 embedding 换成 bge-m3 一并上移；全部可按环境变量覆盖）
ALM_PURPOSE_FILTER_THRESHOLD=0.30  # 目的回归过滤
ALM_ABSTAIN_COS=0.48               # 弃权硬下限
ALM_ABSTAIN_VERIFY_HI=0.60         # 弃权模糊带上界
ALM_GRAPH_DEDUP_THRESHOLD=0.92     # 语义去重
```

> **为什么换 embedding**：平台 smoke 的实测语料以英文为主（add 入参 CJK 仅 24.5%、46 条 query
> 仅 1.2%），而原先用的 `bge-large-zh-v1.5` 是中文专用模型。四个阈值是**余弦阈值、与 embedding
> 模型强绑定**，故随模型一并重标；完整依据见 [版本变更记录](版本变更记录.md) §三。

> **env 文件**：容器运行时**不读**仓库根目录的 `.env`——那份供 MCP / 可视化面板使用，
> 含 `ARIADNE_*`、`NEO4J_*`、`JUDGE_*` 等，ALM 一个都不读。ALM 的全部变量来自同目录的
> `.env.alm`，由 `docker-compose.alm.yml` 的 `env_file` 注入；compose 的 `environment`
> 段只钉 `ALM_HOST` / `ALM_PORT` / `ALM_DATA_DIR` / `EMBEDDING_LOCAL=false` 四项，
> 其余（含 `OPENAI_*`、`EMBEDDING_API_BASE/_API_KEY/_MODEL`、`ALM_API_KEYS`、
> `ALM_LLM_THINKING`）一律由 `.env.alm` 提供。**部署时只需上传该文件**。
>
> 启动命令：`docker compose --env-file .env.alm -f docker-compose.alm.yml up -d`
> （带上 `--env-file` 是为了让端口插值也走同一来源；不带时端口取默认 8770。）

> 平台不需要向本服务注入任何凭据；若部署环境仅放通 LLM 端点而不放通 embedding 端点，
> 可改用镜像内预置的本地向量模型（`--build-arg EMBEDDING_LOCAL=true`）——但该模式
> 需 GPU 或可接受显著更高的内存/镜像体积，云主机上不建议。

## 四、容量与限流声明

| 项 | 值 |
|---|---|
| Add 并发 | 支持 16–64（平台可选区间） |
| Search 并发 | 支持 16–256（平台可选区间） |
| 单请求超时（我方一侧） | 平台客户端默认 1200s（连接超时 10s）；本系统压测最差一次 83.31s，**余量 ≈14 倍** |
| 实测延迟（Add） | 16–25s / 次（本地环境实测，模型 `deepseek-v4-flash`） |
| 实测延迟（Search） | 4.6–8.0s / 次（同上） |
| 单次 Search 返回 | **1 条**：检索到的记忆经整理后的一段叙述（内容即现有 MCP 系统 `dba_query_memory` 对外给出的记忆内容），不超过 `top_k`。叙述通常数百字，属官方指标口径下的 **Compact** |
| 服务端超时与重试 | 上游 embedding 瞬时故障（429 / 超时 / 5xx）内部退避重试至多 4 次（`EMBEDDING_MAX_ATTEMPTS` 可调）；重试耗尽后返回 **5xx 交平台重试**，不静默降级为空结果。LLM 客户端重试 3 次 |
| 限流 | **不主动限流**；如出现容量瓶颈会提前与主办方沟通，不静默降级 |
| 资源需求 | **镜像体积**：`docker save` 导出 tar 148 MB，解包后 722 MB（`ariadne-alm:v0.1.5-alm`，API embedding 模式，无 GPU）。`【待填：容器 CPU / 内存 / 带宽实测值】`（本地向量模型模式需额外内存与镜像体积） |
| 运行成本（token） | Add ≈ $1 / 1000 次、Search ≈ $0.64 / 1000 次（按 gpt-4o-mini 价目表折算，口径见 [0915 压测报告](0915——ALM压测报告.md) §一；实际单价随所用模型变化） |

**实现说明（影响延迟与成本）**：Add 侧单次请求触发 3 次 LLM 调用（维护判断、节点抽取、
连边），Search 侧 2 次（检索目的推断、记忆整理）。**评分本身不计时**，但工业榜的榜单列包含
Write / Search / Total Time 与 Return Size，这些运行指标会被公示，故仍需控制在合理区间。

## 五、数据合规

| 义务 | 本系统的落实方式 |
|---|---|
| 数据仅用于本次评测 | 记忆按 `user_id` 隔离存储，不参与任何其他用途；不做聚合分析 |
| 不用于训练 / 微调 / 分析 / 共享 | 不构建训练集、不外发、不跨团队共享；检索严格限于同一 `user_id` |
| 30 天内删除 | 提供留存清理命令 `python -m alm.cleanup --older-than-days 30 [--apply]`（默认预演），按文件 mtime 删除**整个** `user_id` 空间（图谱 + 索引）。**执行时机必须晚于「接口 ≥30 天可访问」义务期**（见 §1.2），且**须先停服务**再清理——引擎退出会把内存驻留空间重新落盘，运行期删除会被写回（见 `alm/cleanup.py` 顶部说明）。**关键不变量**：落盘仅在空间确有改动时发生（`MemorySpace._dirty`），因此「停服」本身不会刷新 mtime——否则停服后所有空间都会被判为「刚刚写入」，清理会静默空转、看起来成功但什么都没删 |
| 避免留存正文日志 | 记忆正文只存在于 `/data`（评测产物）；运行日志仅含数值、计数与掩码 ID；`dba_pipeline` 下可能打印节点内容节选的 logger 被显式钉在 WARNING 以上，不随日志级别参数放开。**提交版本的 `ALM_TRACE_IO` 必须为关闭状态（默认即关闭）**——该开关是为冒烟期排障准备的输入输出留痕，一旦开启会把请求与返回正文写进容器日志，与本节口径冲突；服务启动横幅会单列一行显示其状态，便于复核 |
| 密钥保护 | 两个 Key 均不入库、不入 URL、不出现在截图 / 邮件正文；`.env` 与 `.env.alm` 均在 `.gitignore` |

> 说明：服务端不做请求正文落盘；如排查需要，也会在恢复后按上述命令清理。
> **（0925 补充）** 唯一例外是显式开启 `ALM_TRACE_IO` 的冒烟排障窗口：该窗口内的容器日志含正文，
> 因此须与 30 天留存清理一并处理（日志轮转 `max-size: 10m / max-file: 3` 只界定了容量，
> 不构成删除义务的履行——容器日志不随 `alm.cleanup` 删除）。
