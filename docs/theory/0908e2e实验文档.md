# e2e 实验论文文档（实验方法 · 实验对象 · 实验数据整理）

> 本文档面向**公开论文**「实验设置 / Experimental Setup」章，独立成文。聚焦**情感陪伴场景下三套记忆系统的端到端（e2e）对照评测**，给出实验方法、实验对象与实验数据整理。
>
> **摘要**：在情感陪伴（系统基石）场景下，以**系统喂给模型的结构化记忆上下文块**为评测对象，对 Ariadne（目的驱动联想检索 + 故事化表达）、Mem0、Graphiti（Zep 商业产品的开源检索核）做端到端对照。方法上以**同题并排一次判定 + 多模型交叉 + 匿名化消偏**保证判分可靠性；结果上 **Ariadne 在质量（四模型判分）、成本（单次/会话 LLM 最低）均占优**。本文的**方法论贡献**包括：①将评测对象收敛为"结构化记忆上下文块"（解耦回复模型）；②纳入**判分可靠性分析（匿名化消偏）**，见 §四，量化并消除 judge 的名称/维度偏好；③成本维度区分"内部 LLM token / 检索注入量 / 语义完整性"。

## 一、实验方法

### 1.1 实验目的
在情感陪伴场景下，对三套记忆系统做端到端对照，回答三个问题：
1. **质量**：谁组装出的"将喂给模型的结构化记忆上下文"作为陪伴素材更好？
2. **一致性/稳健性**：不同 judge 模型对"哪套系统更好"的判断是否一致？
3. **成本**：记忆系统**自身**的检索/写入 LLM 开销谁更低、是否随数据规模增长？

### 1.2 评测对象：结构化记忆上下文块
- 定义：系统经检索 → 组装后、**实际将喂给下游回复模型**的那段结构化记忆文本。三系统形态统一映射为三类：
  - **Ariadne = `{story}`**（走故事化表达，属其系统管线一部分）
  - **Mem0 = `{memories}`**（扁平记忆文本列表）
  - **Graphiti = `{entities,relations}`**（实体 / 关系结构）
- **不生成回复做判分**：把回复模型与记忆系统**解耦**，judge 只评"该块作为陪伴素材的质量"，避免比较回复模型能力。

### 1.3 判断方式：同题并排一次判定 + Rubric
- **同题并排一次判定**：每条查询把**三系统上下文块同题一起**交 judge，在一起比对后各打 1–5 分（相对比对，避免绝对打分全 5 天花板）。
- **Rubric（陪伴场景 3 维，各 1–5 分）**：

| 维度 | 含义 |
|------|------|
| 记忆丰富度 | 记忆信息是否足够丰富、能支撑充分的陪伴（5=非常丰富，1=单薄贫乏） |
| 易理解性 | 这段上下文是否条理清晰、便于直接用（5=一目了然，1=晦涩零乱） |
| 用户建模度 | 能否据此准确理解用户、形成用户画像（5=很强，1=很弱） |

- **judge 参数**：`temperature=0`；同一 judge 会话内完成同题并排（**同批**，不跨批次混排）。judge 提示词附带边/节点类型语义说明（因果 / 同场景 / 时序 / 偏好 / 社交 / 属性 / 时间 / 分类等），避免判分方对结构化块作字面臆测。
- **judge 稳定性**：作为**独立一致性子实验**（多次判分取均值、统计跨次标准差），不混入主判分。

### 1.4 交叉一致性（多模型 judge）
- **动机**：陪伴场景判分主观性强，且判分模型可能存在同源偏置 → 交叉模型验证为**必要条件**。
- **判分模型**：主判分 `qwen3.8-flash`（非 deepseek 系）；交叉 `gemini-3.7-flash` / `gpt-5.6-luna` / `deepseek-v4-flash`。
- **一致性指标**：两两 **top-1 一致率** + **Cohen κ** + **Spearman 秩相关**；并按中文 / 英文分组测语言·文化偏差。

### 1.5 公平性协议
- **同尺度**：同数据、同查询、同指标、同判定、同 embedding（bge-large-zh-v1.5）。
- **同批次**：候选 → 组装上下文块 → 判分全部在同一 judge 会话完成。
- **同候选配额**：候选数按 Ariadne 输出量 N 动态对齐。
- **同组装形态**：三系统产物统一映射为 `{story}`/`{memories}`/`{entities,relations}`，用同一判分提示词，保证判断侧无差异（差异只来自检索 / 组装输入）。

### 1.6 实验前提
| 项 | 前提 |
|----|------|
| 模型本地化 | embedding 与判分模型均本地/固定接入；评测链路不联网下载权重 |
| 依赖隔离 | 重型记忆框架（向量库、分词等）独立依赖目录，评测脚本显式使用 |
| 判分接入 | 判分模型经统一配置接入，判分客户端直连、绕开系统代理 |
| 判分稳健性 | 对推理型判分模型，限制其输出长度并强制结构化输出，避免因推理 token 挤占导致 JSON 截断而误判为"无分" |
| 版本锁定 | gold 图谱、对话语料、查询集、规模数据均版本化（小规模是大规模的前缀子集） |

> ⚠️ 前提红线：实验脚本必须满足"依赖在路径 + 模型本地化 + 离线 + 判分直连"，否则环境不一致导致不可复现。

### 1.7 统计口径与适用范围声明
- **样本量**：查询集 **76 条**（缓解小样本不给精确排位）；每类 2–14 条；主判分看**非弃权 70 条**。
- **统计立场**：小样本 / 分情境（2–4 条）**不给精确排位结论**，给**方向 + 区间**；检索命中类数字带波动，不做精确对比依据。总均分 = 每题 judge 对该题上下文块一次判分再平均。
- **方差子实验**：对判分稳定性做**三次重跑**（story/raw × qwen/deepseek/gpt/gemini × 3），统计跨次标准差；同一 judge 不同重跑结果高度可复现（见 §3.4.4）。
- **适用边界声明**：本文全部**质量结论（判分 / 排位 / 消融 / 偏好）**均限定于**人工构造的纯情景记忆数据集（gold 图谱 163 节点/252 边 + 76 条第一人称倾诉查询）+ 同一批 comprehensive 数据** 这一条件；对真实对话噪声、多用户、真实回复生成等未覆盖场景，**结论需谨慎外推**。判分结论给出**方向 + 区间**而非精确小数；token 结论为**记忆系统内部检索/写入 LLM 开销**，**不计嵌入模型与回复侧 token**。

## 二、实验对象

### 2.1 被测系统（基线）
| 系统 | 实现 | 说明 |
|------|------|------|
| **Ariadne**（被测） | 目的驱动的联想检索 + 故事化表达 | 按需（tool-calling）检索；上游由 LLM 自动维护记忆图谱 |
| **Mem0** | 中文补丁（统一分词 + 中文命名实体），向量 + 稀疏检索混合 | 补丁只动检索侧（词形还原 + 实体识别），不动抽取侧；入库不触发 LLM 抽取 |
| **Graphiti** | 自托管 + Neo4j，时态图谱 + 三路混合检索 | 作为 **Zep 的商业产品之开源核心 Graphiti** 对齐基线（注意：Zep 本身为商业产品，开源仅其核心） |

**基线披露（对齐口径，论文表述）**：
- **Zep 是商业产品，开源的是其核心 Graphiti（Graphiti ≠ 完整 Zep，缺上下文组装层）**：Zep 本身为**商业/闭源**（SaaS + 托管基础设施），**开源的核心是 Graphiti**（抽取 + 时态图谱 + 三路混合检索）。本实验使用**开源 Graphiti**作为 Zep 的对齐检索核，但**不等同于完整商业 Zep**：缺 `thread.get_user_context` 的**近 4 个 episode 图遍历 + 基于最大边际相关性（MMR）的重排**，也缺商业 Zep 的托管设施（多租户隔离、SLA）。因此 **Graphiti 基线代表"Zep 开源检索核"，而非完整商业 Zep**；若需逼近完整 Zep，需在检索后再加一层 MMR 重排（本文未启用）。
- **Mem0 图谱模块未启用（范式限定，影响面有限）**：Mem0 内部同样内置**图谱 / 实体模块**（与 Graphiti 同源的图记忆范式）。本实验使用其**默认向量 + 稀疏检索（BM25）**模式。需要说明：该未启用选项**大概率不影响本文核心结论**，因为对照基线 Graphiti 本身即图谱结构——即 Mem0 未启用图谱，只使 **Mem0 与 Graphiti 的对比**处于不同检索范式（向量+BM25 vs 图谱），属**不对称对照**；但**不影响 Ariadne 占优的核心结论**（Ariadne 占优来源于内容形态完整的上下文块与更低的内部成本，与 Mem0/Graphiti 谁用图谱无直接关系）。同时，"Mem0 检索注入恒定"的结论仅适用于默认模式；启用图谱后其检索注入将随图规模增长（与 Graphiti 同）。
- **Neo4j 中文全文索引缺口**：全文检索对中文按单字 token 索引（需自定义 Lucene 分词器，未做）；混合检索实际由向量 + 图遍历承担。

> **适用性提醒**：上述基线偏差意味着——**Ariadne 与"默认向量+BM25 的 Mem0 / Zep 开源检索核（Graphiti）"作对比**。①Graphiti 缺"完整商业 Zep"的上下文组装层（MMR 重排）+ 托管设施，故"优于 Graphiti"**≠"优于完整 Zep"**；②Mem0 图谱未启用，使 **Mem0 vs Graphiti 为不同检索范式（向量+BM25 vs 图谱）的不对称对照**——但**这两点均不影响 Ariadne 占优的核心结论**（其来源于内容形态完整的上下文块与更低的内部成本）。凡涉及"优于 Mem0 / Graphiti"的表述，均限定于上述对齐口径。

### 2.2 数据集（主评测）
| 资产 | 内容 |
|------|------|
| gold 图谱 | **163 节点 / 252 边**（用户 82 / 助手 44 / 时间锚点 37；7 个生命周期场景） |
| 对话语料 | **26 批双主体口语对话**（用户事实 + 助手自身行为），覆盖 163/163；16/26 批触发时序 |
| 查询集 | **76 条陈述触发式**（用户第一人称倾诉，非问答），9 类能力维度 |

**能力融合**：完整生命周期叙事（高中 → 大专 → 工作 + 7 类查询）+ 双主体（用户事实 + 助手自身行为）+ 事件级时间锚点（时序链 + 跨期时间线重建）。

**规模数据（token 侧）**：50 / 100 / 200 三档**同源递增**内容（小规模是大规模的前缀子集），用于测写入 / 抽取 / 检索随规模的变化。

### 2.3 查询集类别分布（76 条）
| 类别 | 条数 | 类别 | 条数 |
|------|:---:|------|:---:|
| single_fact | 14 | assistant_behavior | 8 |
| temporal | 10 | mixed_memory | 8 |
| multi_hop | 9 | cross_scene | 7 |
| preference | 8 | knowledge_update | 6 |
| abstention（弃权） | 6 | **合计** | **76** |

> 扩充说明：为缓解小样本，查询集由 30 扩至 76 条；新增 40 条充分利用 gold 图谱中此前未覆盖的 73 个节点，每条锚定真实节点。

### 2.4 对齐口径
- **同 embedding**：bge-large-zh-v1.5。
- **数据准备绕过 LLM 抽取**：直接把 gold 图谱编排成各框架所需格式（Mem0 节点内容原文入库；Graphiti 节点 / 边直接建图，仅生成 embedding，不触发 LLM 抽取）。
- **同候选配额**：先跑 Ariadne 全量候选得每条查询 N，Mem0 / Graphiti 截断到该 N。
- **上下文块**：Ariadne=`{story}`（唯一走故事化）、Mem0=`{memories}`、Graphiti=`{entities,relations}`。

### 2.5 评测边界（不作评分的对象）
- ✗ 不对检索候选打分；✗ 不对故事单独打分；✗ 不对"回复"打分。
- 只对"系统组装、将喂给模型的结构化记忆上下文块"打分。

### 3.3 token 成本数据（三维对比：写入单次 / 会话级 / 检索注入）

**核心结论：Ariadne 单次与会话级 LLM 成本最低且不随图规模增长；唯有 Graphiti 检索注入随规模线性放大；Mem0 的"恒定"源自 top_k=8 硬截断（牺牲深度/丰富度）。**

> ⚠️ **口径注记**：本表（§3.3）为**检索侧 scale 实验**（N=50/100/200）口径——**Mem0 用默认 `top_k=8`、Graphiti 设 `limit=4096`**，均为**暴露真实规模趋势**、**未对齐 Ariadne 配额**。**注意区分**：在**质量评测（§3.2 判分的上下文块）**中，**Mem0 / Graphiti 是 D2 同配额对齐到 Ariadne 的候选数 N**（先取 Ariadne 候选 N，再截断 Mem0/Graphiti），与该节口径不同。

| 系统 | 单次写入 (LLM token，随规模) | 会话级 (6轮+1换话题) | 检索注入 (随规模) | 检索侧 LLM | 检索完整性 |
|------|:---:|:---:|:---:|:---:|:---:|
| **Ariadne** | **2394（恒定，最低）** | **~18k（最低）** | 故事 ~330–420 token（恒定，候选 26） | search=2 次 | **完备覆盖（种子可达 + 目的约束内完整）** |
| Mem0 | ~9230–10175（恒定） | ~58k | 8 条 / ~217–267 token（**scale 默认 top_k=8**） | 0（非 LLM） | **受限（scale 截断损失；质量评测已 D2 对齐 Ariadne N）** |
| Graphiti | ~10419–10524（恒定） | ~63k | facts 50→210 / token 888→3635（**随规模≈2×增长**） | 0（非 LLM） | 随规模放大 |

**关键机制解释**：
- **Ariadne 候选恒 26 —— 归因于"图结构 + 目的约束下的种子可达完备性"，而非笼统的"机制自然收敛"**：针对该查询，从**起点种子节点出发**、在**目的回归/约束内**可达的因果链节点集合**恰好为 26**。当图规模从 50→200 时，**新增的节点并不在该查询种子的可达因果链上**（即没有增加这些种子"可辐射到"的因果链节点），故候选数恒为 26。→ 它是**"该查询目的约束下、种子可达集的完备覆盖"**（不遗漏、不膨胀），是**图结构特殊性（种子可达因果链有限）+ 目的回归拦截**共同作用的结果，**不是**"检索器随意封顶"，也**不是**"随图规模自适应收敛"。
- **Mem0 返回恒 8 = 检索侧 scale 实验默认 `top_k=8`（未对齐 Ariadne 配额）**：库内可能有更多相关记忆但只取前 8，代价是检索深度/丰富度下降，且库越大被砍掉的潜在相关记忆越多（该损失不体现在 token 数里）。**但注意**：这是 §3.3 检索侧实验（暴露规模趋势）的设定；在**质量评测（§3.2）**里 Mem0 / Graphiti 已**D2 同配额对齐到 Ariadne 的 N**，并非恒 8。
- **Graphiti 返回 facts 50→210（随规模增长）**：检索侧实验设 `limit=4096` 不人为截断，暴露**图遍历返回的子图规模随图膨胀**——它是三者中唯一"检索注入随规模放大"的。
- → 综上：Ariadne 的"恒 26"（种子可达完备）与 Mem0 的"恒 8"（scale 默认 top_k 截断）**性质不同**，且与 Graphiti 的"随规模增长"（图遍历放大）三者口径各异；跨表对比时**不可把"恒定"混为一谈**。

## 四、判分可靠性分析（匿名化消偏 + 名称/维度偏好）

> **方法论定位**：这是本文**判分方法学贡献**的核心——用**匿名化消偏 + 多模型交叉**，量化并消除 judge 对"系统名称"与"评分维度"的偏好，从而给"谁更好"一个**去偏、可复现**的结论。本节独立于主判分，作为可靠性子实验。

### 4.1 目的与设计
- **目的**：检验"带系统名称 + 三维明细 rubric"是否给判分引入**名称偏好 / 维度偏好**；并区分**匿名化**与**取消三维明细**两个变量的独立作用。
- **设计**：口径仍为**三系统对照打分 1–5 总分 + 排名**，仅叠加两个提示词变量：
  - **匿名化**：把三系统匿名化为 **A / B / C**，每条查询用固定种子**随机打乱** A/B/C 与真实系统的对应（避免位置偏好），不透露名称。
  - **取消三维明细**：只打整体总分，不细分三维；额外要求 judge 返回**一句总体短评**（揭示其偏好理由）。
  - **关键交互**：设「**不匿名 + 取消三维**」变体（保留真实系统名），与「匿名 + 取消三维」对照 → 把"匿名化"与"取消三维"拆开。
- **判分模型**：qwen（主判分）+ deepseek / gemini / gpt-5.6-luna（zh/en 各半）；**两次独立复测**（换 seed，匿名打乱顺序随之改变）检验稳定性。
- **对比基准**：带名 + 三维明细的判分（judge_comprehensive / judge_deepseek）。

### 4.2 结果①：三系统总分均（1–5，非弃权 70 条；同一模型分「三维明细 / 不匿名+取消三维 / 匿名+取消三维」）
> 口径：三维明细 = judge 按三维评分后的均值；取消三维 = judge 直接打的总分。

- 匿名总分均 Ariadne：qwen 4.41 / deepseek 3.77 / gemini 4.50 / gpt 4.24，**四模型均第一**。
- 匿名 vs 带名 top-1 一致率：qwen 81.4%、deepseek 54.3%、gemini 85.7%、gpt 67.1%。

### 4.6 结论（名称反应：中文 vs 英文模型；"知名度"假说被否定）
1. **名称反应只存在于中文模型**：qwen（**+0.27~+0.31**，两次复测）/ deepseek（**+0.49~+0.56**）匿名后 Ariadne 明显回落；而 gemini（0.04）/ gpt（0.02）**几乎无差**——即匿名化只显著影响**中文模型**，英文模型对名称不敏感。
2. **"知名度"假说不成立**：若名称光环来自"知名度"，则更认识 Mem0 / Graphiti（均为知名开源记忆系统）的 gpt / gemini 应在**不匿名**时抬 Mem0 / Graphiti；但实测 gpt（Mem0 3.26→3.40、Graphiti 3.31→3.43）与 gemini（Mem0 3.43→3.41、Graphiti 2.97→3.05）在匿名后**反而略升或持平**，并未因"更知名"而得到加成。→ 名称光环**不是知名度**，而是**中文模型对 "Ariadne" 名称的正向先验**。
3. **取消三维影响很小**：同为"带名"，三维明细 vs 取消三维的差（qwen 0.05、deepseek 0.16、gemini 0.02、gpt 0.17）均小于各自的匿名效应（或几乎可比）；三维 vs 单维不造成明显主观放大。
4. **Ariadne 占优在"纯内容 + 跨模型"下仍稳健**：**英文模型（gpt/gemini）匿名下 Ariadne 仍最高**（gpt 4.24 vs Graphiti 3.43；gemini 4.50 vs Graphiti 3.05），且它们对名称无偏置 → Ariadne 占优主要来自**内容形态（连贯叙事 / 因果链）**，而非名称。
5. **含义**：判分应优先采用**匿名 + 跨 zh/en 多模型**：匿名可去除**中文模型**的名称光环，英文模型本身无此偏置（可作"内容真实性"对照）。"Ariadne 占优"在纯内容判断下成立，**幅度以匿名 + 英文模型视野更可信**。

> **短评佐证（形态偏好）**：即使匿名，qwen 的短评绝大多数明确偏好"**连贯叙事 + 因果链 + 完整背景**"（对应 Ariadne 的故事化形态），并批评其它块"**碎片化 / 罗列 / 平铺直叙 / 偏离主题**"；少数条的短评赞赏"**结构化关系 / 因果链条**"（对应 Graphiti 形态）→ 判分偏好来自**内容形态（完整性 / 连贯性 / 因果链）**本身，而非系统名称。
